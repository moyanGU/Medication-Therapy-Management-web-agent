- 完成跨平台用药提醒的稳定性提升：推送→短信/邮箱兜底、延迟/响应闭环、性能指标可观测

## 项目上下文要点

- 后端：Django + DRF，提醒历史与统计端点位于 `backend/apps/reminders/history_views.py:203`（`metrics`）
- 通道升级与响应闭环：`backend/apps/reminders/views.py:614`（`respond_by_subscription`）与 `scheduler` 实施；短信通道 Spug 已有集成与测试
- API 客户端处理双层 `data`：`src/utils/api.ts:197-203`

## 技术方案
### 架构对齐
- 保持现有 SW 注入策略与 push → `respond_by_subscription` → 历史记录闭环
- 调度器仅对 `pending` 历史重试与通道升级，不重复创建记录
- 统一 API 响应解包与错误处理，不增代理与模拟数据

### 接口契约（四要素示例）
- `GET /reminder-history/metrics/?days=7`
  - 请求：查询参数 `days:number`
  - 响应：`{success:boolean,data:{sent,failed,pending,avg_response_delay_minutes,channel:{push_sent/sms_sent/email_sent/push_failed/sms_failed/email_failed},response_rate,escalation:{escalated_total/escalated_sent/escalation_success_rate}}}`
  - 认证：JWT Bearer
  - 备注：仅汇总当前用户数据
- `POST /reminders/respond_by_subscription/`
  - 请求：`{endpoint:string,response_type:'taken'|'skipped'|'delayed',history_id?:number,reminder_id?:number,delay_minutes?:number}`
  - 响应：`{success:boolean,data:{history_id:number}}`
  - 认证：JWT Bearer
  - 备注：`delayed` 创建补发 `pending` 历史，默认 5 分钟，可由 SW 动作传入 10/30
