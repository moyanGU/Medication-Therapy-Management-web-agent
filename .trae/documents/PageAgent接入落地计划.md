# Page Agent 接入落地计划

## 目标

- 将 `page-agent-main` 的页面驻留 Agent 能力接入 `mtm-helper`
- 首期先落地“页面只读分析”，避免直接引入表单写入和自动提交风险
- 复用现有 `AiAssistant.vue` 入口，不新增独立 React 面板
- 通过后端代理 LLM 请求，避免在前端暴露模型密钥

## 已完成的前置判断

- `mtm-helper` 当前已有全局 AI 助手入口、语音播报、页面元数据与受保护路由
- `page-agent-main` 的核心能力可拆为：
  - `@page-agent/core`：Agent 工作流、工具系统、生命周期钩子
  - `@page-agent/page-controller`：页面 DOM 观察、滚动、元素交互
  - `packages/mcp`：后续可扩展为浏览器任务编排
- 直接把模型密钥放前端不安全，因此首期采用“前端 Agent + 后端 OpenAI 兼容代理”方案

## 首期落地范围

### 范围内

- 在现有 AI 助手中新增“页面助手”模式
- 仅支持提醒页、药品页、仪表板的只读页面分析
- 支持的任务示例：
  - 总结当前页面信息
  - 提炼提醒风险和异常状态
  - 解释当前药品页面的关键字段
  - 根据当前页内容给出下一步建议
- 后端新增 `Page Agent` 专用 LLM 代理接口

### 暂不纳入

- 自动点击提交
- 自动填写并保存表单
- 任意 JavaScript 执行
- 多标签页控制
- 外站自动化
- MCP 编排模式

## 技术方案

### 前端

- 新增 `pageAgentService.ts`
- 懒加载 `@page-agent/core` 与 `@page-agent/page-controller`
- 使用只读工具集运行 Agent：
  - 禁用点击
  - 禁用输入
  - 禁用下拉选择
  - 禁用脚本执行
- 复用现有 `AiAssistant.vue` 对话框作为宿主 UI
- 通过认证请求头调用后端 `/api/ai/page-agent/chat/completions/`

### 后端

- 新增 `POST /api/ai/page-agent/chat/completions/`
- 使用现有百川模型配置作为统一模型出口
- 固定由服务端注入模型名和鉴权
- 返回 OpenAI 兼容响应结构，供 Page Agent 直接消费

## 安全约束

- 前端不保存第三方模型密钥
- 首期仅开放只读分析任务
- 页面助手默认只在登录态可用
- 当前页不在允许范围时直接拒绝执行
- 对消息数、工具数、超时时间做服务端边界控制
