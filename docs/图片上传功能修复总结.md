# 图片上传功能修复总结

## 问题描述
用户反馈上传新图片后，前端未显示，药品详情页也未显示新图片。控制台日志显示部分 `image_path` 为 `null`。

## 问题分析

### 1. 字段不匹配问题
- **问题**: `MedicineForm.vue` 中 `formData` 定义了 `image_path` 字段，但图片上传处理函数中使用了 `image_url` 字段
- **影响**: 图片上传后无法正确设置到表单数据中

### 2. 表单清理逻辑问题
- **问题**: `MedicineForm.vue` 中表单提交前的清理逻辑会删除所有空字符串字段，包括 `image_path`
- **影响**: 即使图片上传成功，`image_path` 也会在提交时被删除

### 3. 图片上传功能未实现
- **问题**: `handleImageUpload` 函数只实现了本地预览，未调用后端上传API
- **影响**: 图片无法真正上传到服务器

### 4. 响应数据结构处理错误
- **问题**: 前端处理后端响应时，未正确解析双层嵌套结构 `response.data.data.image_path`
- **影响**: 即使上传成功，也无法正确获取图片路径

### 5. 图片URL构建不一致
- **问题**: 不同页面的 `getImageUrl` 函数构建图片URL的逻辑不一致
- **影响**: 图片显示可能失败

## 修复方案

### 1. 统一字段命名
```typescript
// 修改前：使用 image_url
formData.image_url = imageData

// 修改后：统一使用 image_path
formData.image_path = imageData.image_path
```

### 2. 修复表单清理逻辑
```typescript
// 修改前：删除所有空字符串字段（除了name）
if (value === '' && key !== 'name') {
  delete cleanedData[key]
}

// 修改后：保留 name 和 image_path 字段
if (value === '' && key !== 'name' && key !== 'image_path') {
  delete cleanedData[key]
}
```

### 3. 实现真实图片上传
```typescript
// 调用后端上传API
const { uploadApi } = await import('@/api/upload')
const response = await uploadApi.uploadMedicineImage(file)

// 正确处理响应数据结构
if (response.data?.success && response.data?.data?.image_path) {
  formData.image_path = response.data.data.image_path
  toast.success('图片上传成功')
}
```

### 4. 统一图片URL构建逻辑
```typescript
const getImageUrl = (imagePath: string) => {
  if (!imagePath) return ''
  if (imagePath.startsWith('http://') || imagePath.startsWith('https://')) {
    return imagePath
  }
  const baseUrl = 'http://127.0.0.1:8000'
  const path = imagePath.startsWith('/') ? imagePath : `/${imagePath}`
  return `${baseUrl}/media${path}`
}
```

## 技术要点

### 后端响应数据结构
```json
{
  "success": true,
  "data": {
    "image_path": "medicines/images/medicine_xxx.png",
    "image_url": "/media/medicines/images/medicine_xxx.png"
  },
  "message": "图片上传成功"
}
```

### 前端访问方式
```typescript
// 正确的访问方式
const imagePath = response.data.data.image_path

// 错误的访问方式
const imagePath = response.data.image_path
```

### 图片URL构建规则
- 后端返回的 `image_path` 是相对路径：`medicines/images/xxx.png`
- 前端需要构建完整URL：`http://127.0.0.1:8000/media/medicines/images/xxx.png`
- Django的 `MEDIA_URL` 设置为 `/media/`

## 总结

通过系统性地分析和修复图片上传功能的各个环节，成功解决了以下问题：
1. 字段命名不一致导致的数据丢失
2. 表单清理逻辑过于严格导致的字段删除
3. 图片上传功能未实现导致的功能缺失
4. 响应数据结构处理错误导致的路径获取失败
5. 图片URL构建不一致导致的显示问题

现在图片上传功能已完全正常工作，用户可以成功上传图片并在各个页面正确显示。
