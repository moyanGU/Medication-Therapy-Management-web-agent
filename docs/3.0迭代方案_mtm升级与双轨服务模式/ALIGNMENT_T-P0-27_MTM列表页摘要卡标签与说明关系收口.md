# ALIGNMENT_T-P0-27_MTM列表页摘要卡标签与说明关系收口

## 一、原始任务

任务来源：

- 基于已完成的 `T-P0-26 MTM 列表页摘要卡上方说明结构与信息优先级收口`

当前继续方向：

- 让摘要卡顶部标签不再沿用旧口径
- 让标签与正文说明共用同一条结果语义主线

---

## 二、当前项目理解

### 2.1 当前已具备的能力

当前列表页摘要卡已经完成：

- 正文说明按优先级收口为单一主上下文说明
- 底部“列表结果”说明区按当前结果场景动态变化
- 分页状态已收口到唯一展示位

因此当前还残留的体验问题是：

- 摘要卡顶部第一枚标签仍沿用旧的入口来源口径
- 正文与底部说明已经切换到“当前结果类型”口径
- 顶部标签、正文说明、底部说明还没有完全共用一个语义源

这会导致：

- 顶部标签像在说“你从哪来”
- 正文和底部说明在说“你现在看到的是什么结果”
- 同一区块内仍存在轻微语义分叉

### 2.2 为什么这是 `T-P0-27` 最合理的最小范围

`T-P0-26` 已经把摘要卡正文说明结构收口完成。

当前继续做最自然的一步，不是再动正文或按钮，而是把摘要卡顶部标签也收口到当前结果语义：

- 主标签表达当前结果类型
- 数量标签表达当前结果规模
- 若存在首页预设，再补一个次级来源标签

因此本轮最合理的最小范围是：

- 只处理摘要卡顶部标签语义
- 只调整标签与说明之间的关系
- 不改变动作、分页、正文说明逻辑和列表行为

### 2.3 当前项目的真实使用场景

当前 MTM 列表页仍以患者端轻量浏览为主，因此本轮更适合：

- 让用户一眼看懂当前结果属于哪类视图
- 让标签和正文不再各说一套

而不是：

- 扩展新的标签系统
- 调整动作入口
- 改造列表项或分页行为

## 三、现有代码约束

### 3.1 当前模板约束

当前 `MtmServiceCasesPage.vue` 摘要卡顶部有两枚标签：

1. `presetSourceBadge`
2. `当前结果 {{ pagination.count }} 条`

其中第一枚强调的是入口来源，第二枚强调的是数量。

最小改法应是：

- 保留顶部标签区域
- 让主标签改为“当前结果类型”
- 让来源标签退为存在首页预设时的补充标签

### 3.2 当前状态约束

本轮必须继续复用现有状态：

- `presetSource`
- `presetSourceBadge`
- `resultSectionCopy`
- `pagination.count`
- `summaryContextCopy`

也就是说，本轮可以改的是：

- 标签文本
- 标签优先级
- 标签与正文说明的语义关系

不应改动：

- 按钮行为
- 正文说明优先级逻辑
- 底部说明区逻辑
- 查询参数和分页行为

### 3.3 当前范围约束

根据当前阶段目标，本轮必须严格保持：

- 只改 `src/pages/MtmServiceCasesPage.vue`
- 不改接口
- 不改路由
- 不改 `src/utils/mtm.ts`
- 不改首页、详情页、空态、底部分页条和列表项卡片

## 四、需求边界确认

### 4.1 本任务要做什么

本任务负责：

- 收口摘要卡顶部标签与正文说明的语义关系
- 让标签与当前结果类型保持一致
- 在有首页预设时保留一个次级来源标签
- 补充本轮对齐、共识、验收文档

### 4.2 本任务不做什么

本任务不负责：

- 修改正文说明内容
- 修改快捷动作和推荐动作逻辑
- 修改页码状态和分页行为
- 修改列表项卡片内容
- 修改接口、路由和 query 参数

---

## 五、关键歧义与当前判断

### 5.1 主标签应该表达入口来源还是结果类型

当前判断：

- 表达结果类型

原因：

- 当前页面主路径已经围绕“当前结果是什么”收口
- 入口来源更适合做补充信息，而不是主标签

### 5.2 首页预设来源标签是否要完全删除

当前判断：

- 不删除，降为次级标签

原因：

- 首页预设来源仍有解释价值
- 但不应该继续压过当前结果语义

### 5.3 是否要把数量标签并入正文

当前判断：

- 不并入

原因：

- 数量标签在顶部很直观
- 本轮只调整语义关系，不减少必要状态信息

---

## 六、建议实现边界

### 6.1 前端修改内容

建议只修改：

- `src/pages/MtmServiceCasesPage.vue`

### 6.2 建议最小实现方式

建议新增一个结果视图元信息 `computed`，统一输出：

1. 当前结果标题
2. 当前结果描述
3. 主标签文案
4. 主标签样式

并完成：

1. 顶部第一枚标签改为当前结果类型
2. 保留数量标签
3. 存在首页预设时再追加一个次级来源标签

### 6.3 建议交付表现

本轮页面首版建议具备：

1. 标签和正文说明语义一致
2. 用户一眼就能看懂当前结果属于哪类视图
3. 页面结构仍保持小步、可回滚

---

## 七、风险点

### 7.1 标签改完后来源语义消失

如果完全拿掉来源语义：

- 首页预设入口价值会变弱

因此本轮应保留次级来源标签，而不是彻底移除。

### 7.2 标签和正文再出现重复堆叠

如果把正文文案原样塞回标签：

- 会显得冗长

因此标签应只保留短语义，不重复整段说明。

### 7.3 为标签单独再造一套判断分支

如果标签逻辑和正文逻辑分开维护：

- 后续又会重新漂移

因此本轮应让标签和说明尽量共用同一份派生结果。

---

## 八、当前结论

`T-P0-27` 最合理的最小范围确定为：

- `MTM 列表页摘要卡标签与说明关系收口`

推荐实现方向：

1. 不改动作、分页和正文行为
2. 不改接口、路由和工具函数
3. 仅在 `MtmServiceCasesPage.vue` 中让顶部标签与结果说明共用同一语义源
4. 让摘要卡顶部形成“结果类型标签 -> 数量标签 -> 可选来源标签”的清晰关系
