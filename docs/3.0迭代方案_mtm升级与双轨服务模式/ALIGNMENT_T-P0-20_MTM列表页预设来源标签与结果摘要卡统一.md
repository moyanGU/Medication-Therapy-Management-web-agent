# ALIGNMENT_T-P0-20_MTM列表页预设来源标签与结果摘要卡统一

## 一、原始任务

任务来源：

- 基于已完成的 `T-P0-19 MTM 列表页预设来源空态与筛选提示细化`

当前继续方向：

- 将 MTM 列表页分散的来源提示、筛选摘要和结果说明统一成一个摘要区
- 让用户进入列表页后，第一眼就能看懂当前来源、当前范围和结果概况

---

## 二、当前项目理解

### 2.1 当前已具备的能力

当前项目已经具备：

- 首页 MTM 入口预设统一
- 列表页 `preset_source` 来源识别
- 列表页来源提示条
- 列表页当前条件摘要
- 列表页更细的人话空态说明

因此当前真正缺的，不是新的筛选能力，而是：

- 列表页顶部提示区域仍然分散
- 来源提示、结果说明、筛选摘要之间还没有形成一个稳定结构

### 2.2 为什么这是 `T-P0-20` 最合理的最小范围

当前列表页的说明已经足够细，但呈现方式还是分散的：

- 顶部来源提示条
- 列表标题下的描述
- 额外一行“当前条件”

这会导致：

- 信息存在，但入口不够聚合
- 用户需要来回看不同位置才能理解当前页面状态

如果现在继续做：

- 更多预设类型
- 更复杂的筛选器
- 列表页更重的组件体系

会继续扩功能，而不是先把已存在信息组织好。

因此当前最合理的最小范围是：

- 把这些已存在信息统一为“来源标签 + 结果摘要卡”

### 2.3 当前项目的真实使用场景

当前项目仍然以患者端直观浏览为主。

因此本轮更适合：

- 统一信息组织方式
- 提高列表页第一屏可理解性

而不是：

- 再增加更复杂的数据操作能力

---

## 三、现有代码约束

### 3.1 当前列表页结构约束

当前 `MtmServiceCasesPage.vue` 中，列表页顶部已有：

- 页面标题
- 来源提示条
- 统计卡
- 筛选区
- 列表标题区说明

因此本轮最合适的改法是：

- 在列表页内容区上方新增一个统一摘要卡
- 把来源与当前结果说明整合进去

而不是：

- 重构整页布局
- 打散统计卡或筛选区

### 3.2 当前文案工具约束

当前 `src/utils/mtm.ts` 已有：

- 来源标题文案
- 来源说明文案
- 当前筛选摘要
- 空态标题与说明

因此本轮应复用并轻量扩展这些工具，而不是重写另一套文案逻辑。

### 3.3 风格约束

当前列表页整体是：

- 卡片式
- 人话文案
- 首屏信息较清晰

因此摘要区也应延续：

- 卡片式
- 可快速扫读
- 不堆技术参数

## 四、需求边界确认

### 4.1 本任务要做什么

本任务负责：

- 为 MTM 列表页增加统一的结果摘要卡
- 在摘要卡中统一展示：
  - 预设来源标签
  - 结果总数
  - 当前说明
  - 当前条件摘要
- 让现有分散提示收敛到同一信息区
- 补充本轮对齐、共识、验收文档

### 4.2 本任务不做什么

本任务不负责：

- 新增后端接口
- 新增筛选器
- 新增更多预设
- 重构首页入口
- 重构列表页分页和详情逻辑

这些内容超出“来源标签与结果摘要卡统一”的范围。

---

## 五、关键歧义与当前判断

### 5.1 旧的来源提示条是否保留

当前判断：

- 不单独保留

原因：

- 本轮目标就是统一，不需要重复展示同一层语义

### 5.2 摘要卡里要展示哪些信息

当前判断：

- 首版展示四类：
  - 当前来源标签
  - 当前结果规模
  - 当前页面说明
  - 当前条件摘要

原因：

- 足够解释当前列表
- 不会过重

### 5.3 空态时摘要卡是否保留

当前判断：

- 保留

原因：

- 即使没有结果，用户也需要知道当前是按什么条件在看

### 5.4 统计卡要不要和摘要卡合并

当前判断：

- 不合并

原因：

- 统计卡展示的是全局概况
- 摘要卡展示的是当前列表上下文
- 两者语义不同

## 六、建议实现边界

### 6.1 前端修改内容

建议修改：

- `src/utils/mtm.ts`
- `src/pages/MtmServiceCasesPage.vue`

### 6.2 列表页新增能力

列表页首版建议具备以下能力：

1. 统一结果摘要卡
2. 来源标签显示
3. 当前结果说明显示
4. 当前条件摘要显示
5. 空态时仍保留摘要区

---

## 七、风险点

### 7.1 信息重复

如果摘要卡做完后，旧提示还全部保留：

- 页面会显得重复

因此本轮需要适度收敛旧提示位置。

### 7.2 摘要卡过重

如果把所有筛选细节、排序、统计都堆进去：

- 页面会失去第一眼可读性

因此首版只保留最重要的解释信息。

### 7.3 预设来源和手动筛选语义混乱

如果来源标签和当前条件摘要没有清楚分层：

- 用户会误以为它们是一回事

因此摘要卡需要明确分工：

- 来源标签：你从哪里来
- 当前条件：你现在怎么看

---

## 八、当前结论

`T-P0-20` 最合理的最小范围确定为：

- `MTM 列表页预设来源标签与结果摘要卡统一`

推荐实现方向：

1. 不新增后端接口
2. 不扩展筛选能力
3. 用一个统一摘要卡收敛来源、结果、条件三层信息
4. 保留空态与已有逻辑，只优化组织方式
5. 以“用户一进列表页就能快速理解当前上下文”为本轮交付目标
