# ALIGNMENT_P1-B1_药学问诊表单最小落地

## 1. 原始需求

- 用户要求在完成当前工程治理后继续业务开发。
- 结合现有总拆分文档，下一条默认业务主线为 `P1-B1 药学问诊表单`。

## 2. 项目上下文理解

### 2.1 当前已存在能力

- 后端已在 `apps.mtm` 中具备 `MTMServiceCase` 与 `MTMInterview` 模型。
- `MTMInterview` 已有可复用的最小字段：
  - `basic_info_snapshot`
  - `medication_history`
  - `allergy_history`
  - `lifestyle_info`
  - `economic_context`
  - `health_expectations`
  - `notes`
  - `completed_at`
- 后端当前仅暴露：
  - `MTM 服务单创建`
  - `MTM 服务单列表`
  - `MTM 服务单详情`
  - `MTM 服务单状态流转`
- 前端当前仅有：
  - `MTM 服务单列表页`
  - `MTM 服务单详情页`
  - 详情页可展示问诊摘要，但还没有问诊编辑入口。

### 2.2 当前缺口

- 没有独立的问诊表单页。
- 没有 `MTMInterview` 的新增/保存/更新接口。
- 没有草稿保存与恢复编辑能力。
- 详情页虽然能展示问诊摘要，但不能进入结构化填写。

## 3. 任务边界

### 3.1 本轮建议纳入

- 为 `P1-B1` 提供最小可用的药学问诊表单闭环。
- 允许用户从现有 MTM 服务单进入问诊填写。
- 支持草稿保存。
- 支持恢复编辑。
- 支持关键字段完整性检查。
- 与当前 `MTMServiceCase.status = interviewing` 状态对齐。

### 3.2 本轮明确不纳入

- 不做 SOAP 编辑。
- 不做 PMR / MAP 导出。
- 不做药师工作台。
- 不做复杂角色授权。
- 不做 AI 自动生成问诊内容。
- 不做跨端协同或多人同时编辑。

## 4. 默认最小实现路径

### 4.1 推荐主路径

- 入口放在现有 `MTM 服务单详情页`。
- 当服务单处于 `pending` 或 `interviewing` 时，提供“开始/继续问诊”主动作。
- 新增独立路由页承接问诊编辑，不在详情页内直接堆大型表单。
- 后端新增 `MTMInterview` 的获取/保存接口，按 `service_case` 一对一维护。
- 首次进入时：
  - 若已有问诊记录，则回填已有内容
  - 若无问诊记录，则基于当前用户资料生成最小空草稿
- 表单先做“手动保存草稿”，不在第一轮强制做自动保存。
- 表单提交完成后：
  - 写入 `completed_at`
  - 允许把服务单从 `pending/interviewing` 推进到下一状态，或至少回到详情页可见已填写摘要

### 4.2 推荐字段分组

- 基础信息
  - 年龄 / 性别 / 身高体重 / 主要诊断等，优先映射到 `basic_info_snapshot`
- 当前与既往用药
  - 映射到 `medication_history`
- 过敏与不良反应
  - 映射到 `allergy_history`
- 生活方式
  - 映射到 `lifestyle_info`
- 经济与依从性背景
  - `economic_context`
- 本次目标与补充说明
  - `health_expectations`
  - `notes`

## 5. 关键约束

- 必须复用现有 `MTMInterview` 数据结构，避免另起一套平行模型。
- 必须与当前 `MTMServiceCase` 详情页、状态流转、列表页保持一致。
- 返回结构继续遵循当前后端统一包裹格式。
- 前端不能使用模拟数据。
- 保持当前 Vue + Django 既有风格，不引入新表单框架。

## 6. 当前识别到的关键决策点

### 6.1 是否需要第一轮就做“自动保存”

- 方案 A：只做“手动保存草稿”
  - 优点：最稳、实现最小、回归面最小
  - 风险：用户中途离开前若未保存，草稿不会保留
- 方案 B：首轮就做“自动保存”
  - 优点：体验更顺
  - 风险：接口频率、脏数据状态、错误提示和回填复杂度都会明显上升

### 6.2 问诊完成后是否立即推进状态

- 方案 A：保存完成问诊时，仅写 `completed_at`，状态仍由用户在详情页手动推进
- 方案 B：保存完成问诊时，自动把服务单推进到 `assessing`

当前更推荐：

- 自动保存：先不做，采用手动保存草稿
- 状态推进：先保持手动推进，避免第一轮把“表单保存”和“状态流转”耦合在一起
