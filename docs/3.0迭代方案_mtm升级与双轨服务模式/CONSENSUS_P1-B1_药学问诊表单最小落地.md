# CONSENSUS_P1-B1_药学问诊表单最小落地

## 1. 已确认的需求描述

本轮进入 `P1-B1 药学问诊表单` 的最小落地阶段，目标是在现有 `MTMServiceCase` 与 `MTMInterview` 基础上，补齐“进入问诊 -> 结构化填写 -> 手动保存草稿 -> 恢复编辑 -> 标记完成 -> 回到详情查看摘要”的最小闭环。

## 2. 已确认的关键决策

### 2.1 草稿保存策略

- 采用“手动保存草稿”
- 本轮不做自动保存

确认原因：

- 实现范围最小
- 回归面最小
- 不把保存频率、脏数据管理和自动提示复杂度提前带进来

### 2.2 问诊完成后的状态策略

- 采用“仅保存完成状态”
- 保存完成问诊时，只写 `completed_at`
- 不自动把服务单推进到 `assessing`

确认原因：

- 避免把“问诊表单保存”和“服务单状态流转”耦合在同一动作里
- 保持现有服务单详情页的状态推进主路径不变

## 3. 本轮范围

### 3.1 纳入范围

- 新增独立问诊表单页
- 从 `MTM 服务单详情页` 进入问诊页
- 后端新增问诊读取与保存接口
- 支持首次创建问诊草稿
- 支持已存在问诊内容的回填编辑
- 支持手动保存草稿
- 支持关键字段完整性检查
- 支持标记问诊完成
- 回到详情页后可看到更新后的问诊摘要

### 3.2 不纳入范围

- 自动保存
- 自动推进服务单状态
- SOAP
- PMR / MAP
- 药师工作台
- 复杂授权模型
- AI 自动生成问诊内容

## 4. 实现边界

- 数据模型继续复用现有 `MTMInterview`
- 服务单主模型仍为 `MTMServiceCase`
- 前端继续沿用现有 Vue 页面与 `mtmApi` 风格
- 后端继续沿用当前统一响应包裹格式
- 不引入新的表单框架或新的状态管理方案

## 5. 默认主路径

1. 用户从 `MTM 服务单详情页` 点击“开始问诊”或“继续问诊”
2. 进入独立问诊页
3. 若已有 `MTMInterview`，回填已有内容
4. 若没有 `MTMInterview`，后端返回最小空草稿
5. 用户可手动点击“保存草稿”
6. 用户点击“完成问诊”时执行字段完整性校验
7. 校验通过后写入 `completed_at`
8. 返回服务单详情页，继续由用户决定是否推进服务单状态

## 6. 验收标准

### 6.1 后端验收

- 可通过服务单 `id` 读取问诊数据
- 当问诊不存在时，可返回最小空结构或自动创建最小草稿
- 可保存问诊草稿
- 可在完成问诊时写入 `completed_at`
- 接口返回结构符合当前项目统一响应格式

### 6.2 前端验收

- 详情页存在明确问诊入口
- 问诊页可正常回填已有内容
- 可手动保存草稿
- 未完成时离开后，再次进入能恢复上次已保存内容
- 点击“完成问诊”时会对关键字段做完整性检查
- 完成后详情页的问诊摘要更新可见

### 6.3 边界验收

- 不自动推进到 `assessing`
- 不出现模拟数据
- 不破坏现有 MTM 列表页和详情页主路径

## 7. 本轮共识结论

`P1-B1` 采用“独立问诊页 + 手动保存草稿 + 手动推进服务单状态”的最小路径实现。该路径与当前 `MTMServiceCase / MTMInterview` 结构完全对齐，可在不扩大范围的前提下，为后续 `SOAP / PMR / MAP / 药师工作台` 提供稳定基础。
