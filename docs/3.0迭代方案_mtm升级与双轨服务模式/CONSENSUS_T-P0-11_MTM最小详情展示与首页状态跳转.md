# CONSENSUS_T-P0-11_MTM最小详情展示与首页状态跳转

## 一、任务共识

本轮正式启动的开发任务为：

- `T-P0-11 MTM 最小详情展示与首页状态跳转`

目标共识：

- 把首页最近服务状态从静态展示升级为可进入详情
- 让用户可以查看 MTM 服务单的最小详情与关联摘要

---

## 二、范围共识

本任务确定只做以下内容：

1. 新增 MTM 服务单详情页
2. 新增 MTM 详情 API 封装
3. 补充 MTM 详情类型定义
4. 新增前端路由
5. 将首页最近服务状态接成详情跳转

明确不做：

- 新增后端接口
- MTM 列表页
- MTM 状态流转操作按钮
- 问诊/评估/计划/随访编辑功能
- 药师工作台

---

## 三、数据来源共识

本任务确定继续复用现有真实接口：

1. `GET /api/mtm/service-cases/`
2. `GET /api/mtm/service-cases/{id}/`

说明：

- 首页最近状态继续基于列表接口
- 独立详情页直接使用详情接口
- 不新增新的后端聚合接口

---

## 四、路由共识

本任务确定新增路由：

- `/mtm/service-cases/:id`

路由命名建议确定为：

- `MtmServiceCaseDetail`

并同步补齐页面标题与页面用途元数据。

---

## 五、首页跳转共识

首页 MTM 卡片中，以下位置确定可进入详情：

1. 最近服务状态中的每条服务单卡片
2. 存在进行中服务时的明显查看入口

交互共识：

- 不改变现有“发起专业服务”和“刷新服务状态”逻辑
- 仅在现有状态区块上增量加入“查看详情”

---

## 六、详情展示共识

详情页首版确定展示以下信息：

### 6.1 服务单主信息

- `case_number`
- `status`
- `trigger_source`
- `service_goal`
- `notes`
- `started_at`
- `created_at`
- `completed_at`

### 6.2 参与者信息

- 患者基础信息
- 主责药师基础信息

### 6.3 关联摘要

- `interview`
- `assessment`
- `plan`
- `follow_ups`

展示原则共识：

- 优先做人话展示
- 数据为空时给出明确空态
- 不把原始 JSON 直接整块抛给用户

---

## 七、页面能力共识

详情页首版确定具备以下能力：

1. 支持首屏加载
2. 支持错误重试
3. 支持手动刷新
4. 支持返回上一页
5. 支持展示空摘要状态

首版不具备：

- 编辑
- 保存
- 提交状态变更

---

## 十、验收标准

本任务完成后，必须满足以下验收条件：

1. 首页最近 MTM 服务状态可以进入详情页
2. `/mtm/service-cases/:id` 能正常加载真实详情
3. 详情页能展示服务单主信息与关联摘要
4. 空数据时页面不报错且有明确提示
5. 全程不展示模拟数据
6. 前端构建通过

---

## 十一、实施结论

`T-P0-11` 的最终实施方案确定为：

1. 以前端详情承接现有后端详情接口
2. 以首页最近状态作为主入口
3. 用最小详情页打通“发起后可继续查看”的闭环
4. 不扩展额外后端接口和复杂页面体系
