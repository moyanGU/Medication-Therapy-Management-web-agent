# CONSENSUS_T-P0-18_MTM列表页预设来源标识与页面提示统一

## 一、任务共识

本轮正式启动的开发任务为：

- `T-P0-18 MTM 列表页预设来源标识与页面提示统一`

目标共识：

- 让 MTM 列表页能识别自己是从哪个首页预设入口进入的
- 让列表页顶部提示与首页预设入口口径保持一致

---

## 二、范围共识

本任务确定只做以下内容：

1. 为首页 MTM 预设入口增加正式来源标识
2. 列表页解析来源标识并显示统一提示
3. 列表进入详情再返回时保留来源标识
4. 用户手动改筛选时清除来源标识

明确不做：

- 新增后端接口
- 修改列表页筛选能力
- 重构首页入口结构
- 增加更多预设类型

---

## 三、来源标识共识

本轮新增正式 query 参数确定为：

- `preset_source`

合法值共识：

1. `all`
2. `active_status`
3. `suggested_trigger`

说明：

- 直接复用现有共享预设 key
- 不再引入第二套来源枚举

---

## 四、列表页提示共识

列表页页头确定新增：

- 预设来源提示条

提示规则共识：

1. `all` 展示“你当前在看全部专业服务”
2. `active_status` 展示“你当前在看首页推荐的当前阶段服务”
3. `suggested_trigger` 展示“你当前在看首页推荐的同类触发服务”

提示文案要求：

- 尽量人话
- 与首页预设名称保持统一语义

---

## 五、状态保持共识

列表页在以下场景保留 `preset_source`：

1. 首页进入列表页
2. 列表进入详情再返回
3. 仅翻页时

列表页在以下场景清除 `preset_source`：

1. 用户手动搜索
2. 用户切换状态筛选
3. 用户切换触发来源筛选
4. 用户切换排序
5. 用户重置筛选

原因共识：

- 这些动作会改变用户看到结果的来源语义
- 继续保留旧提示会误导用户

---

## 六、实现文件共识

本任务确定修改：

1. `src/types/mtm.ts`
2. `src/utils/mtm.ts`
3. `src/pages/MtmServiceCasesPage.vue`
4. `src/pages/MtmServiceCaseDetailPage.vue`

本轮不修改：

1. `src/pages/DashboardPage.vue`
2. `src/api/mtm.ts`
3. 后端 `apps.mtm` 接口代码

---

## 七、验收标准

本任务完成后，必须满足以下验收条件：

1. 首页预设入口进入列表页时会带 `preset_source`
2. 列表页页头能显示与预设一致的人话提示
3. 列表进入详情再返回后，提示仍然存在
4. 用户手动修改筛选后，预设提示会被清除
5. 前端构建通过

---

## 八、实施结论

`T-P0-18` 的最终实施方案确定为：

1. 为首页预设入口增加正式来源标识
2. 让列表页基于该标识输出统一提示
3. 在详情返回链路中保留该标识
4. 在手动筛选时清除该标识，保证提示真实可信
