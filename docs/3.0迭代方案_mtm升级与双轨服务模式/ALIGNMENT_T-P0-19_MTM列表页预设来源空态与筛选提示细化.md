# ALIGNMENT_T-P0-19_MTM列表页预设来源空态与筛选提示细化

## 一、原始任务

任务来源：

- 基于已完成的 `T-P0-18 MTM 列表页预设来源标识与页面提示统一`

当前继续方向：

- 细化 MTM 列表页在预设来源场景下的空态文案
- 细化 MTM 列表页当前筛选条件的人话提示

---

## 二、当前项目理解

### 2.1 当前已具备的能力

当前项目已经具备：

- 首页 MTM 预设入口统一
- 列表页能识别 `preset_source`
- 列表页页头能提示来源
- 用户手动改筛选时会清除 `preset_source`

因此当前真正缺的，不是新的筛选能力，而是：

- 列表页空态提示还比较泛
- 列表页筛选说明还不够人话

### 2.2 为什么这是 `T-P0-19` 最合理的最小范围

当前列表页虽然已经能说明：

- 你是从哪个首页预设来的

但在两个关键场景里，提示仍然不够具体：

1. 当前结果为空时
2. 当前筛选条件较复杂时

如果现在继续加更多功能：

- 更多预设
- 更多筛选器
- 更多入口

只会让列表页越来越强，但不一定更易懂。

因此当前最合理的最小范围是：

- 把空态和筛选说明先打磨清楚
- 让用户更容易理解“为什么是这些结果”以及“为什么现在没有结果”

### 2.3 当前项目的真实使用场景

当前项目仍然以患者端的人话可理解性为主。

因此本轮重点应放在：

- 更直白的列表页提示
- 更准确的预设来源空态说明

而不是：

- 继续增加复杂配置能力

---

## 三、现有代码约束

### 3.1 当前列表页提示约束

当前 `MtmServiceCasesPage.vue` 已有：

- `presetSourceTitle`
- `presetSourceDescription`
- `listDescription`
- 通用空态标题与说明

但目前空态主要只区分：

- 有筛选
- 无筛选

还没有进一步结合：

- `preset_source`
- 当前状态筛选
- 当前触发来源筛选
- 当前搜索词

### 3.2 当前来源语义约束

当前 `preset_source` 代表：

- `all`
- `active_status`
- `suggested_trigger`

因此本轮空态和提示的细化，必须继续围绕这三类来源来做人话解释。

### 3.3 当前筛选条件约束

当前列表页实际可影响结果的条件为：

- `search`
- `status`
- `trigger_source`
- `ordering`

因此本轮筛选提示也应只围绕这些现有条件展开，不新增更多条件维度。

## 四、需求边界确认

### 4.1 本任务要做什么

本任务负责：

- 细化 MTM 列表页来源提示文案
- 细化 MTM 列表页筛选摘要提示
- 细化 MTM 列表页空态标题与说明
- 让预设来源场景下的空态更贴近用户理解
- 补充本轮对齐、共识、验收文档

### 4.2 本任务不做什么

本任务不负责：

- 新增后端接口
- 新增筛选器
- 新增排序能力
- 修改首页预设结构
- 修改详情页返回机制

这些内容超出“空态与筛选提示细化”的范围。

---

## 五、关键歧义与当前判断

### 5.1 空态优先跟谁走

当前判断：

- 先看 `preset_source`
- 再看手动筛选条件

原因：

- 预设来源是更强的页面上下文
- 能更直接解释“为什么你会看到这个列表”

### 5.2 排序要不要算筛选提示

当前判断：

- 要显示为“当前查看方式”

但不建议：

- 把它算作强筛选

原因：

- 排序会影响用户理解结果顺序
- 但不会像状态或来源那样直接缩小结果范围

### 5.3 搜索词要不要在空态里显示

当前判断：

- 要

原因：

- 搜索词是用户最容易忘记的隐性条件
- 空态里明确说出来，最能帮助用户自查

### 5.4 预设来源为空态是否保留“回首页查看”

当前判断：

- 保留

原因：

- 这是当前患者端最自然的下一步动作
- 不需要新增更复杂的空态按钮体系

## 七、风险点

### 7.1 提示过长

如果文案把所有条件一次性堆叠：

- 页面会显得啰嗦

因此首版应做到：

- 简短
- 可读
- 只展示对当前理解最重要的内容

### 7.2 来源提示和空态提示互相重复

如果来源提示条和空态说明说的是同一句话：

- 会显得重复

因此两者应分工：

- 来源提示解释“你从哪里来”
- 空态提示解释“为什么现在没有结果”

### 7.3 手动筛选后的旧预设文案残留

如果用户改了筛选，但旧预设文案还参与空态生成：

- 会继续误导用户

因此本轮必须延续 `preset_source` 清除逻辑。

---

## 八、当前结论

`T-P0-19` 最合理的最小范围确定为：

- `MTM 列表页预设来源空态与筛选提示细化`

推荐实现方向：

1. 不新增后端接口
2. 不新增筛选能力
3. 重点细化人话提示和空态解释
4. 优先围绕 `preset_source + 当前筛选条件` 输出文案
5. 以“用户能快速理解当前结果与空态原因”为本轮交付目标
