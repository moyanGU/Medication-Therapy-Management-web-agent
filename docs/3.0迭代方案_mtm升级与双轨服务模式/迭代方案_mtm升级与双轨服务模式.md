## 一、"龙虾与养虾池"——隐喻解读与系统定位

### 1.1 隐喻内涵

| 元素 | 隐喻含义 | mtm-helper对应 |
|------|----------|----------------|
| **养虾池** | 提供生存环境、养分、边界的生态系统 | mtm-helper平台：数据承载、业务流程、安全边界 |
| **龙虾** | 智能化主体，具备感知、分析、行动能力的AI Agent | Page Agent + 专业MTM引擎：自动化执行药学问诊、评估分析、干预生成 |

### 1.2 升级目标

```
当前状态: 药品管理工具（静态记录）
         ↓
目标状态: 智能MTM服务平台（动态交互 + 自动评估 + 持续学习）
```

**核心转变**:
- 从"人找功能" → "功能找人"
- 从"被动记录" → "主动评估"
- 从"单点服务" → "全流程闭环"

### 1.3 龙虾在虾池中的角色

```
┌─────────────────────────────────────────────────────────────┐
│                      MTM智能服务平台                          │
│  ┌───────────────────────────────────────────────────────┐  │
│  │                    数据层（养虾池水体）                    │  │
│  │   用户数据 │ 药品数据 │ 用药记录 │ 就医记录 │ 评估档案      │  │
│  └───────────────────────────────────────────────────────┘  │
│                           ↑                                │
│  ┌───────────────────────────────────────────────────────┐  │
│  │                 业务逻辑层（池底生态）                    │  │
│  │   药学问诊 │ 评估引擎 │ 干预生成 │ 随访管理              │  │
│  └───────────────────────────────────────────────────────┘  │
│                           ↑                                │
│  ┌───────────────────────────────────────────────────────┐  │
│  │                 AI Agent层（龙虾）                      │  │
│  │   ┌─────────┐  ┌─────────┐  ┌─────────┐               │  │
│  │   │ 感知龙 │  │ 分析龙  │  │ 行动龙  │               │  │
│  │   │ 虾     │  │ 虾      │  │ 虾      │               │  │
```

## 二、双轨服务模式设计

### 2.1 设计理念

**核心原则**: "智障用户打开应用后，系统能自动识别用户意图并引导至正确轨道"

### 2.2 两条总链路架构

```
┌─────────────────────────────────────────────────────────────────────┐
│                          用户入口（极简识别）                          │
│                                                                     │
│     ┌─────────────────┐         ┌─────────────────┐                │
│     │   快速通道入口   │         │   专业通道入口   │                │
│     │  （一键识别）    │         │  （药师引导）    │                │
│     └────────┬────────┘         └────────┬────────┘                │
│              ↓                            ↓                         │
└──────────────┼────────────────────────────┼────────────────────────┘
               ↓                            ↓
┌──────────────┴────────────────────────────┴────────────────────────┐
│                         双轨服务分流                                │
├────────────────────────────┬───────────────────────────────────────┤
│       【链路A】            │           【链路B】                    │
│   日常家居用药管理           │       专业MTM服务                      │
│   (Self-Service)           │       (Professional MTM)               │
│                            │                                       │
│   目标: 便捷、自动化         │       目标: 专业、合规、闭环             │
│   用户: 患者/家属自主使用     │       用户: 患者 + 药师/医生共同在场      │
└────────────────────────────┴───────────────────────────────────────┘
```

### 2.3 链路A：日常家居用药管理（现有功能闭环）

#### 2.3.1 目标用户画像

```
用户类型:
├── 自主管理型患者
│   └── 能自行操作手机，病情稳定，仅需提醒和记录
├── 家庭照护型
│   └── 家属代为管理，子女帮父母操作
└── 轻量咨询型
    └── 有简单用药问题，不需要完整MTM服务
```

#### 2.3.2 现有功能闭环检查

| 模块 | 当前状态 | 闭环检查点 | 缺失项 |
|------|----------|------------|--------|
| 药品管理 | ✅ 已实现 | 扫码添加、库存预警、过期提醒 | 药品识别AI |
| 用药提醒 | ✅ 已实现 | 定时通知、漏服记录 | 智能服药确认 |
| 用药记录 | ✅ 已实现 | 手动记录 | 自动同步/拍照识别 |
| 用药计划 | ✅ 已实现 | 计划制定 | 计划执行追踪 |
| 就医记录 | ✅ 已实现 | 就诊信息录入 | 与药品关联分析 |

#### Phase 1 安全要求

```yaml
数据安全要求:
  加密标准:
    - 敏感字段: AES-256-GCM
    - 传输层: TLS 1.3
    - 密钥管理: 环境变量隔离
    
  访问控制:
    - 最小权限原则
    - 操作审计日志
    - 异常访问告警
    
  合规检查:
    - 数据脱敏展示
    - 导出需二次确认
    - 删除数据不可恢复
```

## 四、患者个人信息保护——第一权重

### 4.1 保护原则

```yaml
核心原则:
  1. 最小必要: 仅收集服务必需的最少个人信息
  2. 目的限定: 数据仅用于MTM服务目的
  3. 知情同意: 用户充分知情并主动授权
  4. 安全存储: 医疗级数据安全标准
  5. 可控访问: 严格权限控制与审计
  6. 及时删除: 超过保存期限或用户要求时删除
```

### 4.2 数据分级分类

```
┌─────────────────────────────────────────────────────────────┐
│                    数据分级分类体系                            │
├───────────────────┬─────────────────┬───────────────────────┤
│     分级          │     举例        │     保护措施          │
├───────────────────┼─────────────────┼───────────────────────┤
│ L1 高度敏感       │                 │                       │
│ (绝密)            │ 疾病诊断         │ 全加密 + 严格审计      │
│                   │ 完整用药历史     │ 生物识别 + 二次确认    │
│                   │ 基因/遗传信息    │ 专线传输 + 定期检查    │
├───────────────────┼─────────────────┼───────────────────────┤
│ L2 中度敏感       │                 │                       │

```

### 4.3 隐私保护技术措施

| 措施类别 | 具体实现 | 优先级 |
|----------|----------|--------|
| **传输安全** | TLS 1.3全链路加密 | P0 |
| **存储安全** | AES-256-GCM敏感字段加密 | P0 |
| **访问控制** | RBAC细粒度权限 + MFA认证 | P0 |
| **审计追溯** | 操作日志完整记录 + 异常告警 | P0 |
| **数据脱敏** | 展示层脱敏 + 导出二次确认 | P0 |
| **安全删除** | 覆写删除 + 不可恢复验证 | P1 |
| **隐私计算** | 必要时引入联邦学习/差分隐私 | P2 |
