# ALIGNMENT_T-P0-34_MTM列表页空态标题与推荐说明关系收口

## 一、原始任务

任务来源：

- 基于已完成的 `T-P0-33 MTM 列表页空态动作区标题与按钮分组语义收口`

当前继续方向：

- 让空态标题与描述不再和“推荐下一步”块重复解释
- 让空态标题、描述、推荐说明三者职责更清晰

---

## 二、当前项目理解

### 2.1 当前已具备的能力

当前列表页空态区已经完成：

- 推荐下一步已独立成轻量说明块
- 动作区已具备区块说明和按钮分组语义
- 空态与主结果区的层级表达已经基本接近

因此当前还残留的体验问题是：

- 空态标题仍偏泛化说明
- 空态描述和推荐下一步块仍会同时解释“现在该做什么”
- 标题、描述、推荐块三者之间还有轻微重复

这会导致：

- 空态虽然已经分层，但最上面的信息仍不够利落
- 用户在空态首屏会先看到一段状态说明，再看到一段推荐说明，理解成本仍略高

### 2.2 为什么这是 `T-P0-34` 最合理的最小范围

`T-P0-33` 已经把空态动作区分组语义收口完成。

当前继续做最自然的一步，不是再改空态动作区，而是把空态最上方的标题与描述再收一层：

- 标题更像结果状态
- 描述更像当前原因
- 推荐块继续承担“下一步建议”

因此本轮最合理的最小范围是：

- 只处理空态标题、空态描述与推荐说明块的关系
- 只改展示文案组织，不改动作集合
- 不改变按钮行为、分页、路由和列表行为

### 2.3 当前项目的真实使用场景

当前 MTM 列表页仍以患者端轻量浏览为主，因此本轮更适合：

- 让用户先快速知道“现在为什么是空的”
- 再看到“接下来推荐怎么做”

而不是：

- 重写空态动作区
- 修改 quick action 排序算法
- 修改接口或筛选逻辑

## 三、现有代码约束

### 3.1 当前模板约束

当前 `MtmServiceCasesPage.vue` 空态区相关结构为：

1. `emptyStateCopy.title`
2. `emptyStateCopy.description`
3. `emptyStateRecommendationBlock`
4. `emptyStateActionsSectionCopy`
5. `emptyStateActionGroups`

最小改法应是：

- 保留现有结构顺序
- 只让标题与描述改为更贴近结果状态
- 不新增新的空态层级

### 3.2 当前状态约束

本轮必须继续复用现有状态：

- `emptyStateCopy`
- `recommendedAction`
- `emptyStateRecommendationBlock`

也就是说，本轮可以改的是：

- 空态标题文本
- 空态描述文本
- 标题/描述和推荐说明之间的语义关系

不应改动：

- `quickActions` 来源和排序
- `recommendedAction` 逻辑
- 按钮点击行为
- 空态动作区分组逻辑

### 3.3 当前范围约束

根据当前阶段目标，本轮必须严格保持：

- 只改 `src/pages/MtmServiceCasesPage.vue`
- 不改接口
- 不改路由
- 不改 `src/utils/mtm.ts`
- 不改主结果区、首页、详情页、底部分页条和列表项卡片

## 四、需求边界确认

### 4.1 本任务要做什么

本任务负责：

- 收口空态标题与推荐说明关系
- 让空态描述更偏当前状态解释
- 让推荐块继续专注承接“下一步建议”
- 补充本轮对齐、共识、验收文档

### 4.2 本任务不做什么

本任务不负责：

- 修改空态推荐块结构
- 修改空态动作区和按钮分组
- 修改空态动作集合
- 修改接口、路由和 query 参数
- 修改主结果区结构

---

## 五、关键歧义与当前判断

### 5.1 是否需要改 `emptyStateCopy` 的生成逻辑

当前判断：

- 不改来源，只在页面内做轻量二次收口

原因：

- 本轮问题在首屏文案职责，而不是空态策略本身
- 页面内 `computed` 足以完成最小收口

### 5.2 标题是否应该直接说“当前没有结果”

当前判断：

- 应更偏结果状态，但仍保留人话温和语气

原因：

- 标题需要更快建立当前状态认知
- 但不能变得过于机械

### 5.3 推荐块是否要削弱

当前判断：

- 不削弱

原因：

- 推荐块本轮刚刚稳定为主路径承接位
- 本轮应调整标题/描述，而不是再次移动推荐块职责

---

## 六、建议实现边界

### 6.1 前端修改内容

建议只修改：

- `src/pages/MtmServiceCasesPage.vue`

### 6.2 建议最小实现方式

建议新增一个空态头部文案 `computed`，统一输出：

1. 标题
2. 描述

并完成：

1. 标题更偏空态结果状态
2. 描述更偏原因说明
3. 推荐块继续专注下一步建议

### 6.3 建议交付表现

本轮页面首版建议具备：

1. 空态标题、描述、推荐说明三者职责更清晰
2. 空态首屏更短、更顺
3. 页面结构仍保持小步、可回滚

---

## 七、风险点

### 7.1 标题改得过硬

如果标题只剩机械结果说明：

- 会损伤页面友好感

因此本轮标题应更清楚，但仍保持人话语气。

### 7.2 描述被删得过少或过多

如果描述几乎不承接原因：

- 会让推荐块显得跳跃

如果描述又重复推荐内容：

- 会继续啰嗦

因此本轮描述应只承担“为什么现在是空的”。

### 7.3 头部文案和推荐块再次漂移

如果页面另起一套完全独立说法：

- 后续还会再次不一致

因此本轮应让空态头部文案和推荐块继续围绕同一状态语义收口。

---

## 八、当前结论

`T-P0-34` 最合理的最小范围确定为：

- `MTM 列表页空态标题与推荐说明关系收口`

推荐实现方向：

1. 不改主结果区、空态动作区、动作来源、分页和正文行为
2. 不改接口、路由和工具函数
3. 仅在 `MtmServiceCasesPage.vue` 中让空态标题与描述共用新的空态头部文案语义
4. 让空态形成“状态标题 -> 原因说明 -> 推荐说明 -> 动作选择”的稳定顺序
