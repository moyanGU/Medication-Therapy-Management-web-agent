# CONSENSUS_T-P0-25_MTM列表页分页状态与结果说明层级收口

## 一、任务共识

本轮正式启动的开发任务为：

- `T-P0-25 MTM 列表页分页状态与结果说明层级收口`

目标共识：

- 去掉结果区首屏重复的页码信息
- 让分页状态与结果说明保持单一层级表达

---

## 二、范围共识

本任务确定只做以下内容：

1. 收口结果区首屏重复页码展示
2. 保留一个主分页状态展示位置
3. 让结果说明区与分页状态形成更清晰的展示层级

明确不做：

- 修改分页按钮行为
- 修改分页接口、路由和 query 参数
- 修改 `src/utils/mtm.ts`
- 修改列表卡片、首页、详情页和空态
- 扩展新的结果区动作

---

## 三、主路径共识

本轮页面主路径继续保持：

1. 头部承接主动作
2. 摘要卡承接结果摘要与补充动作
3. 说明区承接当前结果浏览说明与主分页状态

补充共识：

- 首屏结果区只保留一个页码状态主位置
- 底部分页条继续承担实际翻页控制职责

---

## 四、实现位置共识

本轮页码主位置确定为：

1. 保留摘要卡下方说明区中的页码状态
2. 去掉摘要卡右上的重复页码

原因共识：

- 说明区更贴近“当前结果如何继续浏览”的语义
- 与 `T-P0-24` 已完成的说明区更容易形成统一块

---

## 五、实现文件共识

本任务确定修改：

1. `src/pages/MtmServiceCasesPage.vue`

本轮不修改：

1. `src/utils/mtm.ts`
2. `src/types/mtm.ts`
3. `src/pages/DashboardPage.vue`
4. `src/pages/MtmServiceCaseDetailPage.vue`
5. `src/api/mtm.ts`
6. 后端 `apps.mtm` 代码

---

## 六、验收标准

本任务完成后，必须满足以下验收条件：

1. 结果区首屏不再同时出现两处相同页码
2. 主分页状态仍然清晰可见
3. 分页按钮与分页行为保持不变
4. 只修改 `src/pages/MtmServiceCasesPage.vue`
5. 前端诊断通过
6. `npm run build` 通过

---

## 七、实施结论

`T-P0-25` 的最终实施方案确定为：

1. 仅收口首屏结果区中的重复页码表达
2. 不碰分页逻辑和数据流
3. 让说明区继续承接当前结果状态
4. 继续以单文件、小步、可回滚方式完成本轮增强
