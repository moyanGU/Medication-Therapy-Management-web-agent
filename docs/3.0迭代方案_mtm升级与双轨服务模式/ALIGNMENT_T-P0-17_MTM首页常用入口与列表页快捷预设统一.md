# ALIGNMENT_T-P0-17_MTM首页常用入口与列表页快捷预设统一

## 一、原始任务

任务来源：

- 基于已完成的 `T-P0-16 MTM 列表页首页入口参数联动与快捷筛选跳转`

当前继续方向：

- 统一首页里所有 MTM 列表入口的预设口径
- 让 MTM 区块快捷跳转与“常用入口”中的 MTM 入口不再各自拼参数

---

## 二、当前项目理解

### 2.1 当前已具备的能力

当前项目已经具备：

- 首页 MTM 区块参数化跳转列表页
- 首页 MTM 区块快捷筛选跳转
- MTM 列表页支持筛选与排序保持
- 列表页与详情页上下文联动

因此当前真正缺的，不是新的筛选能力，而是：

- 首页多个 MTM 入口之间的规则统一
- 首页入口定义的单一事实来源

### 2.2 为什么这是 `T-P0-17` 最合理的最小范围

当前首页已经存在：

- MTM 建议区块入口
- 常用入口体系

如果继续在 `DashboardPage.vue` 中分别写：

- `allMtmListRoute`
- `activeMtm...`
- `suggestedTrigger...`
- `quickActions` 里的独立 MTM 路由

虽然功能可用，但会形成新的维护问题：

- 同一类入口口径分散
- 后续再加入口时容易再次手拼 query
- 首页不同位置的 MTM 导航语义可能逐渐漂移

因此当前最合理的最小范围是：

- 把首页 MTM 列表预设抽成共享定义
- 首页不同入口统一消费这套定义

### 2.3 当前项目的真实使用场景

当前项目仍以患者端首页快速导航为主。

因此本轮更适合：

- 统一入口规则
- 提高导航一致性

而不是：

- 再新增更多 MTM 页面
- 再做复杂首页导航体系

---

## 三、现有代码约束

### 3.1 当前列表预设约束

当前首页 MTM 入口本质上都在做同一件事：

- 进入 `/mtm/service-cases`
- 带上若干预设 query

因此本轮不应继续把预设散落在页面里，而应抽成共享 helper。

### 3.2 列表页参数约束

当前列表页正式支持的 query 仍然只有：

- `status`
- `trigger_source`
- `ordering`

因此首页统一预设也必须继续严格只用这些现有正式参数。

### 3.3 首页结构约束

当前首页已有：

- MTM 建议区块
- 常用入口网格

因此本轮更适合：

- 只补一个 MTM 常用入口
- 并用统一预设驱动它

而不是：

- 重构整块首页常用入口布局

---

## 四、需求边界确认

### 4.1 本任务要做什么

本任务负责：

- 抽取首页 MTM 列表预设共享 helper
- 让首页 MTM 区块快捷跳转复用统一预设
- 在首页“常用入口”中加入 MTM 入口
- 让“常用入口”的 MTM 入口复用同一套预设定义
- 补充本轮对齐、共识、验收文档

### 4.2 本任务不做什么

本任务不负责：

- 新增后端接口
- 修改列表页筛选模型
- 修改详情页返回机制
- 重构首页整体布局
- 增加更多 MTM 快捷预设种类

这些内容超出“首页常用入口与列表页快捷预设统一”的范围。

---

## 五、关键歧义与当前判断

### 5.1 “常用入口”中的 MTM 入口该指向哪里

当前判断：

- 优先使用当前最相关的 MTM 预设

优先级建议：

1. 当前阶段服务
2. 同类触发服务
3. 全部服务

原因：

- 这样最贴近首页当前上下文
- 也避免“常用入口”和 MTM 区块语义冲突

### 5.2 是否要把所有 MTM 预设都放进常用入口

当前判断：

- 不要

原因：

- 常用入口区更适合保留一个主入口
- 具体预设仍放在 MTM 区块里即可

### 5.3 统一的核心标准是什么

当前判断：

- 同一套 helper 生成：
  - 跳转路由
  - 短文案
  - 描述文案

原因：

- 只有这样才是真正统一，而不是仅仅复用 path

## 六、建议实现边界

### 6.1 前端修改内容

建议修改：

- `src/utils/mtm.ts`
- `src/types/mtm.ts`
- `src/pages/DashboardPage.vue`

### 6.2 首页新增能力

首页首版建议具备以下能力：

1. MTM 列表预设抽成共享定义
2. MTM 区块快捷入口通过统一预设渲染
3. 常用入口新增 MTM 卡片
4. 常用入口 MTM 卡片复用统一预设

---

## 七、风险点

### 7.1 统一过程中影响已有入口行为

如果 helper 的默认优先级写错：

- 可能让现有“查看全部”或快捷跳转语义发生偏移

因此本轮必须保证：

- 预设逻辑保持现有行为不变

### 7.2 首页重复出现过多 MTM 入口

如果常用入口也堆太多 MTM 卡片：

- 首页会显得重复

因此常用入口只增加一个 MTM 主入口即可。

### 7.3 共享 helper 只统一路由不统一文案

如果路由统一了，但标题和描述还是各写各的：

- 后续仍会逐渐失控

因此预设 helper 需要同时返回：

- 标题
- 短文案
- 描述
- 跳转目标

---

## 八、当前结论

`T-P0-17` 最合理的最小范围确定为：

- `MTM 首页常用入口与列表页快捷预设统一`

推荐实现方向：

1. 不新增后端接口
2. 抽取共享 MTM 列表预设 helper
3. 首页 MTM 区块和常用入口共用这套预设
4. 常用入口只增加一个 MTM 主入口
5. 以“入口不分散、预设不重复、参数口径一致”为本轮交付目标
