# CONSENSUS_T-P0-30_MTM列表页补充动作区与说明块衔接收口

## 一、任务共识

本轮正式启动的开发任务为：

- `T-P0-30 MTM 列表页补充动作区与说明块衔接收口`

目标共识：

- 让补充动作区不再直接紧贴说明块出现
- 让补充动作区明确成为主路径之后的次级选择

---

## 二、范围共识

本任务确定只做以下内容：

1. 为补充动作区增加轻量标题
2. 为补充动作区增加轻量承接说明
3. 轻量调整说明块与动作区的衔接层级

明确不做：

- 修改补充动作集合
- 修改推荐下一步内容或逻辑
- 修改按钮点击行为
- 修改页码状态和底部分页条
- 修改接口、路由和 `src/utils/mtm.ts`

---

## 三、层级共识

本轮摘要卡相关层级确定为：

1. 结果语义层：标签、标题、首行摘要
2. 说明层：当前上下文与推荐下一步
3. 补充动作层：次级可执行选择

补充共识：

- 推荐下一步继续代表主路径
- 补充动作继续代表补充选择
- 补充动作区需要被明确标注，但不能喧宾夺主

---

## 四、实现方式共识

本轮实现方式确定为：

1. 用页面内 `computed` 输出补充动作区标题与说明
2. 仅在动作区前增加轻量承接文本
3. 保持 `summaryActions` 逻辑和按钮样式不变

原因共识：

- 强化层级，不改行为
- 保持主路径稳定
- 便于继续小步维护

---

## 五、实现文件共识

本任务确定修改：

1. `src/pages/MtmServiceCasesPage.vue`

本轮不修改：

1. `src/utils/mtm.ts`
2. `src/types/mtm.ts`
3. `src/pages/DashboardPage.vue`
4. `src/pages/MtmServiceCaseDetailPage.vue`
5. `src/api/mtm.ts`
6. 后端 `apps.mtm` 代码

---

## 六、验收标准

本任务完成后，必须满足以下验收条件：

1. 补充动作区前出现轻量标题和说明
2. 用户更容易理解补充动作是次级选择
3. `summaryActions` 逻辑和按钮行为保持不变
4. 只修改 `src/pages/MtmServiceCasesPage.vue`
5. 前端诊断通过
6. `npm run build` 通过

---

## 七、实施结论

`T-P0-30` 的最终实施方案确定为：

1. 仅收口补充动作区与说明块的衔接关系
2. 不碰标签、标题、说明块逻辑、分页和数据流
3. 用页面内 `computed` 承接补充动作区标题与说明
4. 继续以单文件、小步、可回滚方式完成本轮增强
