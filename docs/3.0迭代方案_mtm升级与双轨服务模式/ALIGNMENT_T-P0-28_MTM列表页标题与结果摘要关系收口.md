# ALIGNMENT_T-P0-28_MTM列表页标题与结果摘要关系收口

## 一、原始任务

任务来源：

- 基于已完成的 `T-P0-27 MTM 列表页摘要卡标签与说明关系收口`

当前继续方向：

- 让摘要卡标题不再固定写死为“服务列表”
- 让标题和第一行结果摘要不再重复解释当前结果语义

---

## 二、当前项目理解

### 2.1 当前已具备的能力

当前列表页摘要卡已经完成：

- 顶部标签已按当前结果类型动态变化
- 正文主上下文说明已按优先级收口
- 底部“列表结果”说明区已与当前结果语义统一

因此当前还残留的体验问题是：

- 标题仍固定为“服务列表”
- 顶部主标签已经会显示“首页预设结果 / 筛选结果 / 排序结果 / 完整列表”
- 紧接着标题下第一行摘要还会再次解释当前结果

这会导致：

- 标题没有承接当前结果语义
- 标签、标题、摘要三层信息之间还有轻微重复
- 用户进入首屏后，不能从标题直接知道当前结果属于哪类视图

### 2.2 为什么这是 `T-P0-28` 最合理的最小范围

`T-P0-27` 已经把顶部标签与结果语义收口完成。

当前继续做最自然的一步，不是再动标签或说明区，而是把标题和第一行摘要也接到同一条语义线上：

- 标题说当前结果属于哪类视图
- 第一行摘要只做简短承接，不再重复铺陈

因此本轮最合理的最小范围是：

- 只处理摘要卡标题与第一行摘要
- 只调整两者与当前结果语义的关系
- 不改变按钮、分页、正文说明和列表行为

### 2.3 当前项目的真实使用场景

当前 MTM 列表页仍以患者端轻量浏览为主，因此本轮更适合：

- 让标题直接告诉用户“现在看到的是哪类结果”
- 让首屏说明更短、更顺口

而不是：

- 再扩新的结果标签体系
- 改造列表卡片
- 修改接口或查询逻辑

## 三、现有代码约束

1. 顶部标签：`summaryHeaderBadges`

3. 第一行摘要：`listDescription`
4. 当前上下文说明：`summaryContextCopy`
5. 推荐下一步：`recommendedAction.description`

最小改法应是：

- 保留整体结构顺序
- 只让标题和第一行摘要动态化
- 避免新增新的说明段落

### 3.2 当前状态约束

本轮必须继续复用现有状态：

- `resultViewMeta`
- `summaryHeaderBadges`
- `summaryContextCopy`
- `presetSource`
- `hasSearchFilters`
- `hasOrderingChanged`

也就是说，本轮可以改的是：

- 标题文本
- 第一行摘要文本

不应改动：

- 顶部标签关系
- 底部说明区逻辑

- 路由和接口请求

### 3.3 当前范围约束

- 只改 `src/pages/MtmServiceCasesPage.vue`
- 不改接口

## 四、需求边界确认

### 4.1 本任务要做什么

本任务负责：

- 收口摘要卡标题与第一行结果摘要的关系
- 让标题直接承接当前结果类型
- 让第一行摘要改为更短的人话承接
- 补充本轮对齐、共识、验收文档

### 4.2 本任务不做什么

本任务不负责：

- 修改顶部标签结构
- 修改正文上下文说明
- 修改快捷动作和推荐动作逻辑
- 修改页码状态和分页行为
- 修改接口、路由和 query 参数

---

## 五、关键歧义与当前判断

### 5.1 标题应该直接复用结果类型还是保持统一“服务列表”

当前判断：

- 应承接结果类型

原因：

- 当前首屏其余结构已经围绕“当前结果是什么”收口
- 固定标题会拉回旧语义

### 5.2 第一行摘要是否还要继续显示数量

当前判断：

- 不再强调数量

原因：

- 顶部标签和分页状态已经有数量信息
- 第一行摘要更适合承担“这一屏怎么理解”的简短说明

### 5.3 是否需要改动 `src/utils/mtm.ts`

当前判断：

- 不需要

原因：

- 本轮只改页面语义组织方式
- 在页面内新增 `computed` 即可完成最小收口

## 六、建议实现边界

- `src/pages/MtmServiceCasesPage.vue`

并完成：

2. 第一行摘要改为更短的承接文案

### 6.3 建议交付表现

本轮页面首版建议具备：

1. 标题、标签、摘要三者语义一致
2. 首屏信息更短、更顺口
3. 页面结构仍保持小步、可回滚

## 七、风险点

### 7.1 标题改得过长

如果标题写成整句：

- 会影响扫描效率

因此本轮标题应只保留短标题，不放整段解释。

### 7.2 第一行摘要被删得过空

如果只剩标题没有任何承接说明：

- 页面会显得突兀

因此本轮仍应保留一行简短摘要，但避免重复数量和场景说明。

### 7.3 新旧语义同时残留

如果标题改了，但摘要还保留旧结果统计口径：

- 会继续重复

因此本轮应一起收口标题和第一行摘要，而不是只改一个点。

---

## 八、当前结论

`T-P0-28` 最合理的最小范围确定为：

- `MTM 列表页标题与结果摘要关系收口`

推荐实现方向：

1. 不改标签、动作、分页和正文行为
2. 不改接口、路由和工具函数
3. 仅在 `MtmServiceCasesPage.vue` 中让标题与第一行摘要共用结果视图语义
4. 让摘要卡形成“标签 -> 标题 -> 简短摘要 -> 当前上下文 -> 下一步”的清晰顺序
