# ALIGNMENT_T-P0-29_MTM列表页当前上下文与推荐下一步边界收口

## 一、原始任务

任务来源：

- 基于已完成的 `T-P0-28 MTM 列表页标题与结果摘要关系收口`

当前继续方向：

- 让摘要卡里的“当前上下文说明”和“推荐下一步”不再只是连续两行文字
- 让两者的语义边界和视觉边界更清晰

---

## 二、当前项目理解

### 2.1 当前已具备的能力

当前列表页摘要卡已经完成：

- 顶部标签、标题、首行摘要已经共用结果语义
- 当前上下文说明已收口为单一主上下文说明
- 推荐下一步已由 `recommendedAction` 单一路径承接

因此当前还残留的体验问题是：

- “当前上下文说明”和“推荐下一步”仍以两个连续段落直接堆叠
- 两者虽然文案不同，但视觉层级差距很小
- 用户首屏浏览时，容易把“当前是什么”与“下一步做什么”混成同一层信息

这会导致：

- 当前上下文与下一步提示的职责边界不够清楚
- 首屏信息已经收口，但块级关系还不够稳定

### 2.2 为什么这是 `T-P0-29` 最合理的最小范围

`T-P0-28` 已经完成标题与首行摘要的语义收口。

当前继续做最自然的一步，不是再改标题或标签，而是把摘要卡中最后一组仍然紧贴的说明块再收一层：

- 当前上下文说明
- 推荐下一步说明

因此本轮最合理的最小范围是：

- 只处理这两块说明的边界和层级
- 只改展示结构，不改动作定义
- 不改变按钮、分页、路由和列表行为

### 2.3 当前项目的真实使用场景

当前 MTM 列表页仍以患者端轻量浏览为主，因此本轮更适合：

- 让用户一眼区分“你现在看到的是什么”与“接下来建议做什么”
- 继续压缩首屏理解成本

而不是：

- 扩展新的动作体系
- 修改快捷按钮布局
- 改造列表项结构

## 三、现有代码约束

### 3.1 当前模板约束

当前 `MtmServiceCasesPage.vue` 摘要卡相关结构为：

1. 标题和首行摘要
2. `summaryContextCopy`
3. `recommendedAction.description`
4. `summaryActions`

最小改法应是：

- 保留这几个块的顺序
- 仅让 `summaryContextCopy` 与 `recommendedAction` 以更清晰的块级形式展示
- 不新增新的动作入口

### 3.2 当前状态约束

本轮必须继续复用现有状态：

- `summaryContextCopy`
- `recommendedAction`
- `summaryActions`
- `resultViewMeta`

也就是说，本轮可以改的是：

- 说明块的模板结构
- 说明块的展示层级
- 是否通过 `computed` 统一说明块输出

不应改动：

- 快捷动作逻辑
- `recommendedAction` 的来源与内容
- 底部说明区逻辑
- 分页、路由和接口请求

### 3.3 当前范围约束

根据当前阶段目标，本轮必须严格保持：

- 只改 `src/pages/MtmServiceCasesPage.vue`
- 不改接口
- 不改路由
- 不改 `src/utils/mtm.ts`
- 不改首页、详情页、空态、底部分页条和列表项卡片

## 四、需求边界确认

### 4.1 本任务要做什么

本任务负责：

- 收口“当前上下文说明”和“推荐下一步”的边界
- 让两块说明的职责更容易一眼区分
- 继续保持当前主路径只由 `recommendedAction` 承接
- 补充本轮对齐、共识、验收文档

### 4.2 本任务不做什么

本任务不负责：

- 修改顶部标签、标题和首行摘要
- 修改快捷动作和推荐动作逻辑
- 修改页码状态和分页行为
- 修改接口、路由和 query 参数
- 修改列表项卡片内容

## 五、关键歧义与当前判断

### 5.1 是否需要新增一套新的说明文案数据源

当前判断：

- 不需要

原因：

- 当前说明内容已经足够
- 问题在于边界不清，不在于缺内容

### 5.2 是否需要把推荐下一步做成更大的操作卡

当前判断：

- 不需要

原因：

- 当前主操作按钮已经在页面顶部承接
- 本轮只处理说明块，不增加新的交互层

### 5.3 是否需要把上下文说明隐藏掉

当前判断：

- 不隐藏

原因：

- 它仍然承担解释当前结果来源或条件的职责
- 本轮目标是分层，而不是删减关键语义

## 六、建议实现边界

### 6.1 前端修改内容

建议只修改：

- `src/pages/MtmServiceCasesPage.vue`

### 6.2 建议最小实现方式

建议新增一个摘要卡说明块 `computed`，统一输出：

1. 当前上下文块
2. 推荐下一步块

并完成：

1. 两块说明从连续段落改为清晰分层的小块
2. 当前上下文更偏静态说明
3. 推荐下一步更偏行动提示

### 6.3 建议交付表现

本轮页面首版建议具备：

1. 当前上下文和推荐下一步更容易区分
2. 首屏块级关系更稳定
3. 页面结构仍保持小步、可回滚

---

## 七、风险点

### 7.1 分层过度导致块太多

如果额外包太多层：

- 会让页面显得碎

因此本轮应保持最小块级增强，而不是重做卡片布局。

### 7.2 推荐下一步再次抢走主按钮职责

如果把推荐说明做得像新按钮入口：

- 会和页面顶部主操作重复

因此本轮只强化说明边界，不新增新的动作入口。

### 7.3 当前上下文变得过弱

如果只突出推荐下一步而压低上下文：

- 用户可能不知道为什么看到当前结果

因此本轮应同时保留上下文解释，只是降低与动作提示的混淆。

---

## 八、当前结论

`T-P0-29` 最合理的最小范围确定为：

- `MTM 列表页当前上下文与推荐下一步边界收口`

推荐实现方向：

1. 不改标签、标题、动作来源、分页和正文行为
2. 不改接口、路由和工具函数
3. 仅在 `MtmServiceCasesPage.vue` 中让上下文说明与推荐下一步形成更清晰的块级边界
4. 让摘要卡形成“标签 -> 标题 -> 简短摘要 -> 当前上下文 -> 推荐下一步 -> 补充动作”的稳定顺序
