# CONSENSUS_T-P0-28_MTM列表页标题与结果摘要关系收口

## 一、任务共识

本轮正式启动的开发任务为：

- `T-P0-28 MTM 列表页标题与结果摘要关系收口`

目标共识：

- 让摘要卡标题直接表达当前结果类型
- 让标题下第一行摘要改为更短的人话承接

---

## 二、范围共识

本任务确定只做以下内容：

1. 收口摘要卡标题文本
2. 收口标题下第一行结果摘要文本
3. 让标题、标签、底部说明共用同一条结果语义

明确不做：

- 修改顶部标签结构
- 修改正文上下文说明
- 修改快捷动作定义
- 修改页码状态和底部分页条
- 修改接口、路由和 `src/utils/mtm.ts`

---

## 三、层级共识

本轮摘要卡信息层级确定为：

1. 顶部标签：说明当前结果类型与数量
2. 标题：直接承接当前结果视图
3. 简短摘要：用一句话承接当前屏幕应如何理解
4. 当前上下文：补充当前来源或筛选条件
5. 推荐下一步：说明接下来如何继续

补充共识：

- 标题不再固定写死为“服务列表”
- 简短摘要不再重复数量或整段结果说明

---

## 四、实现方式共识

本轮实现方式确定为：

1. 继续扩展现有结果视图 `computed`
2. 用同一份 `computed` 承接标题、简短摘要和底部说明语义
3. 移除仅服务旧摘要的页面内重复计算

原因共识：

- 进一步减少首屏重复文案
- 继续避免语义漂移
- 保持模板结构简单、可维护

---

## 五、实现文件共识

本任务确定修改：

1. `src/pages/MtmServiceCasesPage.vue`

本轮不修改：

1. `src/utils/mtm.ts`
2. `src/types/mtm.ts`
3. `src/pages/DashboardPage.vue`
4. `src/pages/MtmServiceCaseDetailPage.vue`
5. `src/api/mtm.ts`
6. 后端 `apps.mtm` 代码

---

## 六、验收标准

本任务完成后，必须满足以下验收条件：

1. 摘要卡标题不再固定写死为“服务列表”
2. 标题能按当前结果场景正确变化
3. 标题下第一行摘要变为更短的人话承接，且不再重复数量
4. 标题、标签、底部说明语义保持一致
5. 只修改 `src/pages/MtmServiceCasesPage.vue`
6. 前端诊断通过
7. `npm run build` 通过

---

## 七、实施结论

`T-P0-28` 的最终实施方案确定为：

1. 仅收口摘要卡标题与第一行摘要
2. 不碰标签、动作、分页和数据流
3. 用同一份结果视图 `computed` 承接标题、摘要和底部说明语义
4. 继续以单文件、小步、可回滚方式完成本轮增强
