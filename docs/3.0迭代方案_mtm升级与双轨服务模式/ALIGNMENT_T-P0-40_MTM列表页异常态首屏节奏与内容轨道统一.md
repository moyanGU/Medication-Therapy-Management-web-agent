# ALIGNMENT_T-P0-40_MTM列表页异常态首屏节奏与内容轨道统一

## 一、原始任务

任务来源：

- 基于已完成的 `T-P0-39 MTM 列表页空态推荐块与主结果信息块层级统一`

当前继续方向：

- 让异常态首屏与当前空态、主结果区的展示节奏更统一
- 让列表页在“加载失败”时不再回到旧的重块式表达

---

## 二、当前项目理解

### 2.1 当前已具备的能力

当前 `MtmServiceCasesPage.vue` 已经完成：

- 主结果区顶部、底部说明条的层级已经收口
- 空态顶部说明、推荐块、动作区轨道已经收口
- 空态与主结果区之间的大部分展示差异已经被压平

因此当前剩余的最小展示不一致点主要落在异常态：

- `loadError` 仍使用更早期的重间距和更大的图标容器
- 异常态没有与空态相同的内容轨道和首屏密度
- 页面在“空态 / 结果态 / 异常态”切换时，异常态最像另一套旧样式

### 2.2 为什么这是 `T-P0-40` 最合理的最小范围

当前列表页展示层如果还要继续小步推进，最自然的一步不是再改结果区或空态区，而是补齐异常态：

- 异常态与空态都属于首屏说明型状态
- 异常态当前仍是最明显的旧节奏残留
- 只要收口异常态，页面状态分支的展示层就更接近完整闭环

因此本轮最合理的最小范围是：

- 只处理 `loadError` 分支的首屏节奏和内容轨道
- 只改模板结构和样式类，不改错误文案来源
- 不改 loading、空态、主结果区、接口、路由、分页和 `src/utils/mtm.ts`

### 2.3 当前项目的真实使用场景

当前 MTM 列表页仍以患者端浏览为主，因此本轮更适合：

- 让异常态也遵循“先理解当前状态，再执行下一步”的同类节奏
- 让用户在加载失败时仍觉得自己还在同一套页面表达里

而不是：

- 改错误文案逻辑
- 改重试行为
- 改加载逻辑或接口调用

---

## 三、现有代码约束

### 3.1 当前模板约束

当前状态分支主要包括：

1. loading
2. loadError
3. empty
4. non-empty list

其中 `loadError` 当前结构已经具备：

- 图标
- 标题
- 错误说明
- 重试按钮

最小改法应是：

- 保留现有顺序和行为
- 只收口异常态首屏的宽度、间距和图标节奏
- 不新增新的状态层

### 3.2 当前状态约束

本轮必须继续复用现有状态：

- `loadError`
- `refreshPage`

也就是说，本轮可以改的是：

- 异常态外层内容轨道
- 图标容器大小
- 标题、说明、按钮之间的节奏

不应改动：

- 错误文案逻辑
- 重试按钮行为
- 其他状态分支逻辑

### 3.3 当前范围约束

根据当前阶段目标，本轮必须严格保持：

- 只改 `src/pages/MtmServiceCasesPage.vue`
- 不改接口
- 不改路由
- 不改 `src/utils/mtm.ts`
- 不改 loading 分支、空态逻辑、主结果区逻辑、列表项卡片、底部分页条、首页和详情页

## 四、需求边界确认

### 4.1 本任务要做什么

本任务负责：

- 收口异常态首屏节奏与内容轨道
- 让异常态与空态/主结果区更像同一套页面表达
- 保持当前错误文案和重试行为不变
- 补充本轮对齐、共识、验收文档

### 4.2 本任务不做什么

本任务不负责：

- 修改错误文案逻辑
- 修改重试按钮行为
- 修改 loading、空态和主结果区逻辑
- 修改接口、路由和 query 参数
- 修改分页和列表数据流

---

## 五、关键歧义与当前判断

### 5.1 是否需要同时改 loading 分支

当前判断：

- 不需要

原因：

- 本轮要补的是最明显的旧样式残留
- loading 仍是过渡态，异常态更值得优先收口

### 5.2 是否需要新增错误说明块

当前判断：

- 不需要

原因：

- 当前异常态职责已清晰
- 本轮只做节奏统一，不增加新块

### 5.3 是否需要把异常态改成和空态完全一样

当前判断：

- 不需要

原因：

- 异常态仍需保留更明确的警示色语义
- 只要统一轨道和节奏，不必完全同构

---

## 六、建议实现边界

### 6.1 前端修改内容

建议只修改：

- `src/pages/MtmServiceCasesPage.vue`

### 6.2 建议最小实现方式

建议直接在异常态模板样式类上做最小调整：

1. 让异常态外层与空态接近同一内容轨道
2. 收轻图标容器与上下间距
3. 让按钮与说明块之间的节奏更自然

### 6.3 建议交付表现

本轮页面首版建议具备：

1. 异常态首屏更像当前页面体系内的说明状态
2. 状态切换时视觉落差更小
3. 业务逻辑和文案保持原样，仍然小步、可回滚

---

## 七、风险点

### 7.1 异常态被收得太弱

如果过度弱化异常态：

- 会削弱失败状态的警示感

因此本轮只统一节奏，不削弱错误色语义。

### 7.2 把范围扩到 loading 或空态

如果顺手继续动其他分支：

- 会放大本轮范围

因此本轮只改 `loadError` 分支。

### 7.3 改到错误文案逻辑

如果同时调整错误文本来源：

- 会超出本轮展示层范围

因此本轮只动模板样式，不碰错误逻辑。

---

## 八、当前结论

`T-P0-40` 最合理的最小范围确定为：

- `MTM 列表页异常态首屏节奏与内容轨道统一`

推荐实现方向：

1. 不改任何错误逻辑、重试行为和数据流
2. 不改接口、路由、空态区和工具函数
3. 仅在 `MtmServiceCasesPage.vue` 中收口异常态首屏的内容轨道与间距节奏
4. 让列表页状态分支的展示层更接近完整闭环
