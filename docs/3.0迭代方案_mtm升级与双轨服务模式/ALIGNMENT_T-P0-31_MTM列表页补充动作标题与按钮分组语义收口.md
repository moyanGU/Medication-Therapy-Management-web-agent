# ALIGNMENT_T-P0-31_MTM列表页补充动作标题与按钮分组语义收口

## 一、原始任务

任务来源：

- 基于已完成的 `T-P0-30 MTM 列表页补充动作区与说明块衔接收口`

当前继续方向：

- 让补充动作区不只停留在区块级说明
- 让按钮本身也明确属于哪类次级选择

---

## 二、当前项目理解

### 2.1 当前已具备的能力

当前列表页摘要卡已经完成：

- 结果语义层、说明层、补充动作层已初步分开
- 补充动作区已具备轻量标题与承接说明
- 补充动作仍继续复用 `summaryActions`

因此当前还残留的体验问题是：

- 补充动作区整体已经被解释为“次级选择”
- 但按钮本身仍然只是平铺展示
- 用户还看不出这些按钮更偏“辅助操作”还是“切换路径”

这会导致：

- 标题层和按钮层的语义还没完全打通
- 补充动作区虽然不再突兀，但分组语义还不够明确

### 2.2 为什么这是 `T-P0-31` 最合理的最小范围

`T-P0-30` 已经把补充动作区的区块承接补上了。

当前继续做最自然的一步，不是改按钮行为，而是把按钮本身也纳入同一层语义说明：

- 哪些属于辅助操作
- 哪些属于切换路径

因此本轮最合理的最小范围是：

- 只处理补充动作标题与按钮分组语义
- 只改展示结构，不改动作集合
- 不改变按钮行为、分页、路由和列表行为

### 2.3 当前项目的真实使用场景

当前 MTM 列表页仍以患者端轻量浏览为主，因此本轮更适合：

- 让用户理解补充动作不是同一类按钮的简单平铺
- 让按钮分组语义继续服务当前单一路径

而不是：

- 扩展新的按钮动作
- 修改 quick action 排序算法
- 改造按钮样式体系

---

## 三、现有代码约束

### 3.1 当前模板约束

当前 `MtmServiceCasesPage.vue` 补充动作区相关结构为：

1. `summaryActionsSectionCopy`
2. `summaryActions`

最小改法应是：

- 保留区块标题和说明
- 保留 `summaryActions`
- 仅增加按钮分组的人话标题

### 3.2 当前状态约束

本轮必须继续复用现有状态：

- `summaryActions`
- `summaryActionsSectionCopy`
- `recommendedAction`

也就是说，本轮可以改的是：

- 补充动作内部的小组标题
- 按钮分组的展示结构
- 分组的轻量人话描述

不应改动：

- `summaryActions` 的来源和集合
- `recommendedAction` 逻辑
- 按钮点击行为
- 说明块和底部说明区逻辑

### 3.3 当前范围约束

根据当前阶段目标，本轮必须严格保持：

- 只改 `src/pages/MtmServiceCasesPage.vue`
- 不改接口
- 不改路由
- 不改 `src/utils/mtm.ts`
- 不改首页、详情页、空态、底部分页条和列表项卡片

---

## 四、需求边界确认

### 4.1 本任务要做什么

本任务负责：

- 收口补充动作标题与按钮分组语义
- 让按钮分组和补充动作区标题保持一致
- 保持按钮行为完全不变
- 补充本轮对齐、共识、验收文档

### 4.2 本任务不做什么

本任务不负责：

- 修改补充动作集合
- 修改按钮主次样式规则
- 修改推荐下一步内容和逻辑
- 修改分页状态和分页行为
- 修改接口、路由和 query 参数

---

## 五、关键歧义与当前判断

### 5.1 是否需要真的拆成多组按钮

当前判断：

- 可以按现有 `variant` 做轻量分组，但不强求视觉上分很多块

原因：

- 现有动作数量少
- 本轮是语义收口，不是布局重做

### 5.2 如果当前只有一类按钮，是否还要显示分组标题

当前判断：

- 需要

原因：

- 当前问题本来就是语义不够明确
- 即使只有一类按钮，也需要给出人话归类

### 5.3 是否需要为不同动作 key 定制不同文案

当前判断：

- 先不按 key 定制，优先按 `variant` 收口

原因：

- `variant` 已是现成的稳定语义
- 更利于和现有 quick action 体系对齐

---

## 六、建议实现边界

### 6.1 前端修改内容

建议只修改：

- `src/pages/MtmServiceCasesPage.vue`

### 6.2 建议最小实现方式

建议新增一个补充动作分组 `computed`，统一输出：

1. 分组标题
2. 分组说明
3. 分组内按钮列表

并完成：

1. 按 `variant` 对补充动作做轻量分组
2. 给每组补一个人话标题
3. 不改任何按钮行为

### 6.3 建议交付表现

本轮页面首版建议具备：

1. 用户能一眼理解按钮属于哪类补充选择
2. 区块标题与按钮分组语义一致
3. 页面结构仍保持小步、可回滚

---

## 七、风险点

### 7.1 分组做得太重

如果把动作区拆成过多层：

- 会重新增加视觉复杂度

因此本轮只应做轻量分组，不重做版式。

### 7.2 语义和 `variant` 脱节

如果页面文案另起一套规则：

- 后续又会漂移

因此本轮应优先复用现有 `variant`。

### 7.3 次级动作被说得太像主入口

如果分组文案太强：

- 会和推荐下一步抢主路径

因此本轮所有分组文案都必须保持“补充/辅助”语气。

---

## 八、当前结论

`T-P0-31` 最合理的最小范围确定为：

- `MTM 列表页补充动作标题与按钮分组语义收口`

推荐实现方向：

1. 不改标签、标题、说明块、动作来源、分页和正文行为
2. 不改接口、路由和工具函数
3. 仅在 `MtmServiceCasesPage.vue` 中按现有 `variant` 为补充动作补充分组语义
4. 让补充动作区形成“区块标题 -> 分组标题 -> 分组按钮”的稳定表达
