# ALIGNMENT_T-P0-35_MTM列表页空态图标标题与推荐块首屏密度收口

## 一、原始任务

任务来源：

- 基于已完成的 `T-P0-34 MTM 列表页空态标题与推荐说明关系收口`

当前继续方向：

- 让空态图标、标题、描述、推荐块之间的首屏密度更紧凑
- 让空态头部第一屏更像一个完整轻量块，而不是逐段松散堆叠

---

## 二、当前项目理解

### 2.1 当前已具备的能力

当前列表页空态区已经完成：

- 空态标题、原因说明、推荐说明、动作区职责已分开
- 空态动作区已具备标题、分组说明和按钮分组语义
- 空态与主结果区的表达口径已基本统一

因此当前还残留的体验问题是：

- 空态图标、标题、描述、推荐块之间的垂直间距仍偏松
- 空态首屏的注意力会被多段留白切开
- 相比主结果区，空态顶部第一屏略显“散”

这会导致：

- 文案职责已经清晰，但第一眼扫描效率还不够高
- 空态区仍有一点“信息分开了，但没完全聚起来”的感觉

### 2.2 为什么这是 `T-P0-35` 最合理的最小范围

`T-P0-34` 已经把空态头部文案职责收口完成。

当前继续做最自然的一步，不是再改文案逻辑，而是仅收口空态头部的视觉密度：

- 图标更轻一点
- 标题与描述更贴近一点
- 推荐块和头部说明之间更顺一点

因此本轮最合理的最小范围是：

- 只处理空态图标、标题、描述、推荐块的间距与密度
- 只改展示层样式，不改文案来源
- 不改变按钮行为、分页、路由和列表行为

### 2.3 当前项目的真实使用场景

当前 MTM 列表页仍以患者端轻量浏览为主，因此本轮更适合：

- 让空态首屏更容易一眼看完
- 让空态顶部成为一个完整的“先理解状态，再看建议”的轻量块

而不是：

- 重写空态文案
- 改动作分组逻辑
- 改按钮样式体系

---

## 三、现有代码约束

### 3.1 当前模板约束

当前 `MtmServiceCasesPage.vue` 空态区顶部主要由以下结构组成：

1. 图标容器
2. 空态标题
3. 空态描述
4. 推荐说明块

最小改法应是：

- 保留结构顺序
- 只调整容器尺寸、间距和局部留白
- 不新增新的状态层

### 3.2 当前状态约束

本轮必须继续复用现有状态：

- `emptyStateHeaderCopy`
- `emptyStateRecommendationBlock`
- `emptyStateActionsSectionCopy`

也就是说，本轮可以改的是：

- 图标大小与容器大小
- 标题、描述、推荐块之间的间距
- 顶部整体的密度和节奏

不应改动：

- `emptyStateHeaderCopy` 文案逻辑
- `emptyStateRecommendationBlock` 文案逻辑
- 空态动作分组逻辑
- 按钮点击行为

### 3.3 当前范围约束

根据当前阶段目标，本轮必须严格保持：

- 只改 `src/pages/MtmServiceCasesPage.vue`
- 不改接口
- 不改路由
- 不改 `src/utils/mtm.ts`
- 不改主结果区、空态动作区逻辑、首页、详情页、底部分页条和列表项卡片

## 四、需求边界确认

### 4.1 本任务要做什么

本任务负责：

- 收口空态头部首屏的视觉密度
- 让图标、标题、描述和推荐块形成更紧凑的轻量组
- 保持文案职责与交互行为完全不变
- 补充本轮对齐、共识、验收文档

### 4.2 本任务不做什么

本任务不负责：

- 修改空态头部文案
- 修改空态推荐块文案
- 修改空态动作区与按钮分组
- 修改接口、路由和 query 参数
- 修改主结果区结构

---

## 五、关键歧义与当前判断

### 5.1 是否需要把空态改成左对齐

当前判断：

- 不需要

原因：

- 当前空态整体仍适合居中表达
- 本轮目标是密度收口，不是布局重构

### 5.2 是否需要缩小推荐块本身

当前判断：

- 适度缩小留白即可，不改块级职责

原因：

- 推荐块仍是空态主路径承接位
- 只需要减少它与头部的距离和自身 padding 的松散感

### 5.3 是否需要动动作区间距

当前判断：

- 只做轻微协同调整，不作为本轮主目标

原因：

- 本轮重点在空态首屏第一屏密度
- 避免范围重新扩回动作区结构

---

## 六、建议实现边界

### 6.1 前端修改内容

建议只修改：

- `src/pages/MtmServiceCasesPage.vue`

### 6.2 建议最小实现方式

建议直接在模板样式类上做最小调整：

1. 收紧图标容器尺寸
2. 收紧标题与描述间距
3. 收紧推荐块与头部之间的间距
4. 适度降低推荐块内部留白

### 6.3 建议交付表现

本轮页面首版建议具备：

1. 空态首屏更紧凑
2. 空态头部更像一个完整轻量块
3. 页面结构仍保持小步、可回滚

---

## 七、风险点

### 7.1 收得过紧导致压迫感

如果把所有间距都压得太小：

- 会损伤可读性

因此本轮只做轻量收紧，不追求极限紧凑。

### 7.2 误伤文案层级

如果为了紧凑把推荐块做得和描述一样弱：

- 会削弱主路径提示

因此本轮只收紧间距，不改变推荐块层级。

### 7.3 空态与主结果区密度反差过大

如果空态压得太紧而主结果区仍偏松：

- 会让页面不同状态切换时显得突兀

因此本轮调整幅度应保持保守。

---

## 八、当前结论

`T-P0-35` 最合理的最小范围确定为：

- `MTM 列表页空态图标标题与推荐块首屏密度收口`

推荐实现方向：

1. 不改主结果区、空态文案逻辑、动作来源、分页和正文行为
2. 不改接口、路由和工具函数
3. 仅在 `MtmServiceCasesPage.vue` 中收紧空态头部第一屏的视觉密度
4. 让空态形成更紧凑的“图标 -> 标题 -> 原因说明 -> 推荐说明”首屏节奏
