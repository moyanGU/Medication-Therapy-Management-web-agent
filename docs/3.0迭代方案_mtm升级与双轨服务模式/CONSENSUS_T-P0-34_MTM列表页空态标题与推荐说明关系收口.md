# CONSENSUS_T-P0-34_MTM列表页空态标题与推荐说明关系收口

## 一、任务共识

本轮正式启动的开发任务为：

- `T-P0-34 MTM 列表页空态标题与推荐说明关系收口`

目标共识：

- 让空态标题更直接表达当前结果状态
- 让空态描述与推荐说明块职责分开

---

## 二、范围共识

本任务确定只做以下内容：

1. 收口空态标题文本
2. 收口空态描述文本
3. 让标题、描述、推荐说明之间的关系更清晰

明确不做：

- 修改空态推荐块结构
- 修改空态动作区与按钮分组
- 修改空态动作集合
- 修改接口、路由和 `src/utils/mtm.ts`
- 修改主结果区结构

---

## 三、层级共识

本轮空态区层级确定为：

1. 状态标题：直接说明当前结果为空
2. 原因说明：解释当前为什么为空
3. 推荐说明：承接最建议的下一步
4. 动作区：提供可继续选择

补充共识：

- 标题和描述不再重复推荐块职责
- 推荐块继续保留主路径承接位

---

## 四、实现方式共识

本轮实现方式确定为：

1. 用页面内 `computed` 输出空态头部标题与描述
2. 模板直接改为复用该 `computed`
3. 保持 `emptyStateCopy`、`recommendedAction` 和动作区逻辑不变

原因共识：

- 继续保持最小修改
- 明确头部文案职责
- 不影响现有动作体系

---

本任务确定修改：

本轮不修改：

## 六、验收标准

本任务完成后，必须满足以下验收条件：

1. 空态标题更偏结果状态，不再只是泛化说明
2. 空态描述更偏当前原因说明，不再重复推荐内容
3. 推荐说明块仍保留主路径位置
4. 只修改 `src/pages/MtmServiceCasesPage.vue`
5. 前端诊断通过
6. `npm run build` 通过

---

## 七、实施结论

`T-P0-34` 的最终实施方案确定为：

1. 仅收口空态标题与描述
2. 不碰空态推荐块、动作区、分页和数据流
3. 用页面内 `computed` 承接空态头部标题与描述
4. 继续以单文件、小步、可回滚方式完成本轮增强
