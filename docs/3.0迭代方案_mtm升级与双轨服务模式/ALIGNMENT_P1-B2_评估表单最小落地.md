# ALIGNMENT P1-B2 评估表单最小落地

## 1. 原始需求

- 直接继续 `P1-B2`：评估表单最小落地。

## 2. 当前项目上下文

### 2.1 已有基础

- 后端 `apps.mtm` 已存在 `MTMAssessment` 模型。
- 当前模型字段已经覆盖最小评估表单所需核心信息：
  - 五维评分：`appropriateness_score` / `effectiveness_score` / `safety_score` / `adherence_score` / `economic_score`
  - 问题清单：`problem_list`
  - 评估总结：`summary`
  - 综合风险等级：`risk_level`
  - 完成时间：`completed_at`
- 服务单详情接口已经会返回 `assessment` 摘要。
- 服务单详情页已经存在“评估摘要”展示区，但当前没有独立评估填写入口。
- 当前状态流转骨架已支持：
  - `interviewing -> assessing`
  - `assessing -> intervening`

### 2.2 与 P1-B1 的衔接关系

- `P1-B1` 已完成：
  - 独立问诊页
  - 问诊读取 / 草稿保存 / 完成接口
  - 详情页唯一问诊入口
  - 手动保存草稿
  - 完成只写 `completed_at`
  - 不自动推进服务状态
- `P1-B2` 适合沿用同样的主路径风格，保持用户认知一致。

## 3. 当前缺口

- 无独立评估表单页。
- 无评估读取接口。
- 无评估草稿保存接口。
- 无评估完成接口。
- 详情页没有“开始评估 / 继续评估 / 查看已填评估”的唯一入口。
- 当前详情页在 `interviewing` 阶段仍主要依赖状态动作“进入评估”，与表单入口容易形成双路径。

## 4. 本轮任务边界

### 4.1 本轮要做

- 新增独立评估页，承接最小评估填写。
- 新增评估读取 / 保存 / 完成 3 条接口。
- 在服务单详情页接入评估入口。
- 让评估填写完成后可以回到详情页查看摘要。
- 保持页面文案为普通用户可理解的人话。

### 4.2 本轮不做

- 不新增 `MTMAssessment` 数据表字段。
- 不引入新的表单库。
- 不把评估完成和进入干预自动绑定。
- 不在本轮同时落地 `P1-B3` 干预计划表单。
- 不做自动保存。

## 5. 默认主路径判断

- 评估表单复用现有 `MTMAssessment` 字段即可，不需要扩表。
- 评估页继续采用“手动保存草稿 + 手动完成”的双按钮模式。
- 完成评估时只写 `completed_at`，不自动把服务单推进到 `intervening`。
- 服务单状态推进仍保留人工显式动作，和表单完成解耦。
- 详情页应像问诊一样只保留一个主评估入口，避免“进入评估”和“开始评估”并存造成双路径。

## 6. 关键实现假设

- `problem_list` 在前端继续用“每行一项问题”收集，提交时映射为结构化数组。
- 风险等级用固定枚举 `low / medium / high` 承接。
- 五维评分允许为空草稿；完成时再做最小必填校验。
- 只有在问诊已存在且已完成时，才推荐进入评估主路径。
