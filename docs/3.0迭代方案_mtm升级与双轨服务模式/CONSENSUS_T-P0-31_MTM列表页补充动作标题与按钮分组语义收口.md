# CONSENSUS_T-P0-31_MTM列表页补充动作标题与按钮分组语义收口

## 一、任务共识

本轮正式启动的开发任务为：

- `T-P0-31 MTM 列表页补充动作标题与按钮分组语义收口`

目标共识：

- 让补充动作区标题和按钮分组语义保持一致
- 让按钮不再只是平铺，而是带有清晰的人话归类

---

## 二、范围共识

本任务确定只做以下内容：

1. 为补充动作区按钮增加轻量分组标题
2. 为补充动作区按钮增加轻量分组说明
3. 按现有 `variant` 收口按钮分组语义

明确不做：

- 修改补充动作集合
- 修改推荐下一步内容或逻辑
- 修改按钮点击行为
- 修改页码状态和底部分页条
- 修改接口、路由和 `src/utils/mtm.ts`

---

## 三、层级共识

本轮补充动作区层级确定为：

1. 区块标题：说明这是补充选择
2. 分组标题：说明这类按钮的用途
3. 分组按钮：承接具体次级动作

补充共识：

- 所有分组都继续服务于“补充选择”
- 不让任何分组文案抢走主路径语义

---

## 四、实现方式共识

本轮实现方式确定为：

1. 用页面内 `computed` 按 `variant` 对 `summaryActions` 轻量分组
2. 为每个分组输出标题、说明和按钮列表
3. 保持 `summaryActions` 来源、顺序和按钮行为不变

原因共识：

- 继续复用现有 quick action 语义
- 减少模板硬编码判断
- 保持最小改动与后续可维护性

---

## 五、实现文件共识

本任务确定修改：

1. `src/pages/MtmServiceCasesPage.vue`

本轮不修改：

1. `src/utils/mtm.ts`
2. `src/types/mtm.ts`
3. `src/pages/DashboardPage.vue`
4. `src/pages/MtmServiceCaseDetailPage.vue`
5. `src/api/mtm.ts`
6. 后端 `apps.mtm` 代码

---

## 六、验收标准

本任务完成后，必须满足以下验收条件：

1. 补充动作区按钮不再只是平铺展示
2. 按钮分组能用人话说明当前属于哪类补充选择
3. `summaryActions` 来源、顺序和按钮行为保持不变
4. 只修改 `src/pages/MtmServiceCasesPage.vue`
5. 前端诊断通过
6. `npm run build` 通过

---

## 七、实施结论

`T-P0-31` 的最终实施方案确定为：

1. 仅收口补充动作区标题与按钮分组语义
2. 不碰标签、标题、说明块、分页和数据流
3. 用页面内 `computed` 承接分组标题、说明和按钮列表
4. 继续以单文件、小步、可回滚方式完成本轮增强
