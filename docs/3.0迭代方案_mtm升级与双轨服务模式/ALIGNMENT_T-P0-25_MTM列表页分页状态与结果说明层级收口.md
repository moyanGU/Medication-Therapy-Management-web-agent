# ALIGNMENT_T-P0-25_MTM列表页分页状态与结果说明层级收口

## 一、原始任务

任务来源：

- 基于已完成的 `T-P0-24 MTM 列表页底部“列表结果”说明区与当前主路径语义统一`

当前继续方向：

- 让结果区的分页状态表达不再重复出现
- 让“当前在看第几页”只保留一个清晰位置

---

## 二、当前项目理解

### 2.1 当前已具备的能力

当前列表页结果区已经具备：

- 头部主动作已收口到 `recommendedAction`
- 摘要卡补充动作已收口到 `summaryActions`
- 底部“列表结果”说明区已能按场景切换文案

因此当前还残留的体验问题是：

- 同一块首屏结果区里，页码信息出现了两次
- 摘要卡右上已经显示一次“第 X / Y 页”
- 摘要卡下方说明区右侧又再显示一次相同页码

这会导致：

- 同一层信息重复，页面显得散
- 用户不容易判断哪一处才是当前结果区的主分页状态

### 2.2 为什么这是 `T-P0-25` 最合理的最小范围

`T-P0-24` 已经把底部说明区文案改成了跟随当前主路径变化的人话提示。

当前再继续做最自然的一步，不是继续扩文案场景，而是把同一区块里的分页状态表达也收口：

- 只保留一个主分页状态展示点
- 让说明区和分页状态的层级更清晰

因此本轮最合理的最小范围是：

- 只处理结果区中的页码重复问题
- 只调整结果说明区与页码状态的展示层级
- 不改变任何分页行为

### 2.3 当前项目的真实使用场景

当前 MTM 列表页仍以患者端轻量浏览为主，因此本轮更适合：

- 降低页面局部重复信息
- 强化“先看当前结果，再决定是否翻页或进详情”的单一路径

而不是：

- 改造分页逻辑
- 改造卡片内容结构
- 扩展新的筛选或排序能力

---

## 三、现有代码约束

### 3.1 当前模板约束

当前 `MtmServiceCasesPage.vue` 中，页码信息出现在两个位置：

1. 摘要卡右上
2. 摘要卡下方“列表结果”说明区右侧

这两个位置属于同一结果区首屏范围，因此本轮最小改法应是：

- 保留一个主分页状态
- 去掉另一个重复页码

### 3.2 当前数据来源约束

本轮必须继续复用现有状态：

- `pagination.current_page`
- `pagination.total_pages`
- `pagination.count`
- `serviceCases.length`

也就是说，本轮可以改的是：

- 页码显示位置
- 页码配套的人话说明

不应改动：

- 翻页逻辑
- 查询参数同步逻辑
- 接口请求参数

### 3.3 当前范围约束

根据当前阶段目标，本轮必须严格保持：

- 只改 `src/pages/MtmServiceCasesPage.vue`
- 不改接口
- 不改路由
- 不改 `src/utils/mtm.ts`
- 不改首页、详情页、空态和列表项卡片

---

## 四、需求边界确认

### 4.1 本任务要做什么

本任务负责：

- 收口结果区首屏重复的页码信息
- 让结果说明区和分页状态层级更清晰
- 保持当前分页行为完全不变
- 补充本轮对齐、共识、验收文档

### 4.2 本任务不做什么

本任务不负责：

- 修改分页按钮行为
- 修改分页条底部结构
- 修改列表卡片内容
- 修改动作按钮和说明逻辑
- 修改接口、路由和 query 参数

---

## 五、关键歧义与当前判断

### 5.1 是否要同时改底部分页条

当前判断：

- 不改

原因：

- 底部分页条属于实际翻页控制区
- 本轮只处理首屏结果区的重复分页状态

### 5.2 两处页码应该保留哪一处

当前判断：

- 优先保留摘要卡下方说明区中的页码状态

原因：

- 该区域更接近“当前结果如何继续浏览”的说明
- 与 `T-P0-24` 刚完成的说明区更容易形成一个整体

### 5.3 是否需要新增复杂分页文案规则

当前判断：

- 不需要

原因：

- 本轮目标是去重与层级收口
- 不是做新的分页引导系统

---

## 六、建议实现边界

### 6.1 前端修改内容

建议只修改：

- `src/pages/MtmServiceCasesPage.vue`

### 6.2 建议最小实现方式

建议新增一个与页码状态相关的 `computed`，统一输出：

1. 首屏显示的分页状态文案
2. 是否需要展示多页浏览提示

并完成：

1. 去掉摘要卡右上的重复页码
2. 保留说明区中的主分页状态

### 6.3 建议交付表现

本轮页面首版建议具备：

1. 首屏结果区不再重复显示相同页码
2. 结果说明和页码状态形成一个清晰块
3. 页面结构仍保持小步、可回滚

---

## 七、风险点

### 7.1 收口后信息变少

如果直接删掉一处页码但不补清晰主位置：

- 用户可能觉得页码信息不明显

因此本轮应保留一个明确且稳定的主分页状态展示点。

### 7.2 范围误扩到分页逻辑

如果顺手改了翻页逻辑：

- 会超出当前最小范围

因此本轮只改显示层，不改行为层。

### 7.3 说明区再次承担过多职责

如果把页码、推荐动作、结果摘要都挤进同一区域：

- 容易再次变乱

因此本轮只做“重复页码去重 + 主位置收口”。

---

## 八、当前结论

`T-P0-25` 最合理的最小范围确定为：

- `MTM 列表页分页状态与结果说明层级收口`

推荐实现方向：

1. 不改分页行为
2. 不改接口、路由和工具函数
3. 仅在 `MtmServiceCasesPage.vue` 中收口重复页码展示
4. 让结果说明区成为首屏结果状态的单一承接位置
