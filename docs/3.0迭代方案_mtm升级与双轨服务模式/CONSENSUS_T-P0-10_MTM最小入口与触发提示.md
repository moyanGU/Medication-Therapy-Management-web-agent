# CONSENSUS_T-P0-10_MTM最小入口与触发提示

## 一、任务共识

本轮正式启动的开发任务为：

- `T-P0-10 MTM 最小入口与触发提示`

目标共识：

- 把首页已有的 MTM 建议卡片升级为真实可发起入口
- 让用户在首页看到触发原因、发起服务并查看最近状态

---

## 二、入口位置共识

本任务确定：

- 不新建复杂 MTM 页面作为首版入口
- 继续使用 `DashboardPage.vue` 中现有“专业用药指导建议”卡片

原因：

- 已经具备首页聚合上下文
- 能最短路径打通风险提示与真实服务创建
- 符合“最小入口”定位

---

## 三、数据来源共识

本任务确定使用两类真实数据：

1. 首页聚合接口 `GET /api/dashboard/summary/`
2. MTM 服务接口 `GET /api/mtm/service-cases/` 与 `POST /api/mtm/service-cases/`

明确不新增新的后端聚合接口。

---

## 四、前端结构共识

本任务确定新增：

1. `src/types/mtm.ts`
2. `src/api/mtm.ts`

并修改：

- `src/pages/DashboardPage.vue`

不新增：

- 独立 MTM 路由页面
- 独立 MTM store

原因：

- 当前只需首页最小入口
- 不需要引入额外复杂度

---

## 五、卡片能力共识

首页 MTM 卡片首版确定具备以下能力：

1. 展示是否建议进入 MTM
2. 展示触发原因列表
3. 展示“立即发起专业服务”按钮
4. 展示创建中的 loading 状态
5. 展示最近 1 到 3 条服务单状态摘要
6. 若已有进行中的服务单，优先提示当前进度

---

## 六、创建行为共识

点击发起按钮时，确定调用：

- `POST /api/mtm/service-cases/`

创建参数共识：

- `trigger_source` 由当前首页上下文推断
- `service_goal` 由当前首页风险与建议拼成最小人话描述
- `notes` 补充当前触发原因

触发来源首版映射共识：

1. 若依从性偏低，优先用 `adherence_alert`
2. 若存在到期复诊，用 `followup_due`
3. 若药品数量较多，用 `polypharmacy`
4. 其余情况使用 `self_requested`

说明：

- 即使由规则提示触发，动作仍然是用户手动点击发起
- 因此首版不做自动建单

---

## 七、最近状态展示共识

最近服务状态首版确定展示：

- `case_number`
- `status`
- `trigger_source`
- `created_at`

若存在未完成服务单：

- 在卡片中突出显示“当前进行中”
- 默认不鼓励重复创建

若不存在服务单：

- 显示“还没有发起过专业服务”的空态文案

---

## 八、交互体验共识

本任务确定：

- 发起成功后立即刷新服务单列表
- 发起成功后立即刷新首页聚合数据
- 使用 toast 提示成功或失败
- 关键位置打印日志

按钮规则共识：

- 正在创建时禁用重复点击
- 已存在进行中服务时，主按钮改为弱提示或禁用创建

---

## 九、验收标准

本任务完成后，必须满足以下验收条件：

1. 首页能看到 MTM 专业服务入口
2. 首页能展示来自真实数据的触发原因
3. 用户可以从首页手动发起 MTM 服务
4. 发起成功后首页能看到服务状态
5. 已有进行中服务时，首页能提示当前状态
6. 全程不展示模拟数据

---

## 十、实施结论

`T-P0-10` 的最终实施方案确定为：

1. 首页卡片继续作为 MTM 最小入口
2. 前端直接复用现有首页聚合与 MTM 服务单 API
3. 卡片内完成提示、发起和最近状态展示
4. 不扩展独立 MTM 页面，不做复杂自动分诊
5. 以“能看见、能发起、能看到状态”为本轮交付目标
