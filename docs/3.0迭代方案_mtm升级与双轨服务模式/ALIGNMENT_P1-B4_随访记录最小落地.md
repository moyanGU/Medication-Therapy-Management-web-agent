# ALIGNMENT P1-B4 随访记录最小落地

## 1. 原始需求

- 承接 `P1-B3` 干预计划表单的完成，进入 `P1-B4`：随访环节 (`following_up`) 的最小落地。

## 2. 当前项目上下文

### 2.1 已有基础

- 后端 `apps.mtm` 已经存在 `MTMFollowUp` 模型，包含字段：
  - `follow_up_time` (时间)
  - `follow_up_method` (方式，如电话/面谈)
  - `execution_status` (状态，如待执行/已完成)
  - `risk_change` (风险变化)
  - `summary` (总结)
  - `next_follow_up_time` (下次随访时间)
- 服务单详情页 `MtmServiceCaseDetailPage.vue` 已经有了展示 `follow_ups` 数组的 UI 卡片（基于 `MTMFollowUpSummarySerializer`）。

### 2.2 与 P1-B3 的衔接关系

- 问诊、评估、计划三者都是“单服务单 1 对 1”的。
- **随访是“单服务单 1 对 N”的**。一个服务单可以有多次随访。
- 因此，不能像 `get_or_create` 那样处理草稿，而是需要标准的新增、修改（列表或明细）模式。

## 3. 当前缺口

- 后端 `MTMServiceCaseViewSet` 中还没有专门管理子资源（`MTMFollowUp`）的新增/修改接口。
- 前端没有独立表单页来新增和编辑单条随访记录。
- 详情页的随访区块只读，没有入口“添加随访”和“编辑随访”。

## 4. 本轮任务边界

### 4.1 本轮要做

- 为 MTM 服务单提供新增单条随访、更新单条随访的后端 API。
- 新增 `MtmFollowUpFormPage.vue` 组件，复用之前独立表单页的交互（手动保存草稿 / 提交完成）。
- 在详情页提供新增和编辑随访记录的入口，入口控制逻辑：当干预计划已完成后，允许新增随访记录。
- 考虑到“单草稿 vs 多条记录”，本轮允许用户直接新增随访记录（状态可为 `pending` 或 `completed`）。

### 4.2 本轮不做

- 不做复杂的定时任务（自动生成随访任务）。
- 不把单次随访的完成与整个服务单的“已完成”直接硬绑定。
- 不做随访列表的独立分页，依附在服务单详情中返回即可。

## 5. 默认主路径判断

- 详情页新增一个主入口按钮：“添加随访记录”（当干预计划 `completed_at` 存在时可用）。
- 点击某一条随访卡片，可以进入编辑态（`MtmFollowUpFormPage` 需要支持 `followUpId`）。
- 为了降低复杂度，本轮不分“保存草稿”和“完成”，仅保留单一的“保存”动作。在保存时，用户通过选择 `execution_status` 决定它是“待执行”、“已完成”等。
- 随访的填写表单需要校验 `follow_up_time`。
