# CONSENSUS_T-P0-14_MTM列表页与详情页筛选联动和路由查询保持

## 一、任务共识

本轮正式启动的开发任务为：

- `T-P0-14 MTM 列表页与详情页之间的筛选联动 / 路由查询保持`

目标共识：

- 让 MTM 列表页的搜索、状态筛选和页码可以保存在 URL 中
- 让用户从详情页返回时，能回到原来的列表上下文

---

## 二、范围共识

本任务确定只做以下内容：

1. 列表页 `search`、`status`、`page` 同步到路由查询参数
2. 列表页刷新后按查询参数恢复状态
3. 从列表进入详情时带上返回上下文
4. 详情页返回时优先回带查询参数的列表页

明确不做：

- 新增后端接口
- 新增触发来源筛选
- 新增高级排序
- 新增更多列表字段
- 新增额外返回按钮样式改版

---

## 三、查询参数共识

本轮正式保留的查询参数确定为：

1. `page`
2. `search`
3. `status`

详情页附加来源标记共识：

1. `from=mtm-list`

说明：

- 只保留当前列表页已真实使用的核心状态
- 不为未来未开放能力提前扩展复杂查询结构

---

## 四、列表页交互共识

列表页确定具备以下行为：

1. 首次进入时解析 `route.query`
2. 查询参数非法时回退到默认值
3. 用户执行搜索时更新 URL
4. 用户切换状态筛选时更新 URL
5. 用户切换页码时更新 URL
6. 页面刷新后保持当前列表上下文
7. 浏览器前进后退时重新按 URL 恢复列表

实现共识：

- 优先使用 `router.replace`
- 避免搜索和筛选产生过多历史记录

---

## 五、详情页返回共识

详情页返回逻辑确定为：

1. 如果存在 `from=mtm-list`，优先返回 `/mtm/service-cases`
2. 返回时保留 `page`、`search`、`status`
3. 如果不存在列表来源上下文，则保持现有返回逻辑

说明：

- 兼容从首页最近状态直接进入详情的场景
- 不强制把所有详情入口都改成列表返回

---

## 六、实现文件共识

本任务确定修改：

1. `src/pages/MtmServiceCasesPage.vue`
2. `src/pages/MtmServiceCaseDetailPage.vue`

本轮不修改：

1. `src/api/mtm.ts`
2. `src/router/index.ts`
3. 后端 `apps.mtm` 接口代码

---

## 七、实现方式共识

列表页实现共识：

- 增加查询参数解析函数
- 增加本地状态到路由查询的同步函数
- 以路由查询为可恢复上下文来源

详情页实现共识：

- 进入详情链接带上当前列表 query
- 返回按钮优先使用 query 恢复列表

统一要求：

- 保持现有页面结构基本不变
- 关键位置打印日志
- 不引入重复请求或冗余状态

---

## 八、验收标准

本任务完成后，必须满足以下验收条件：

1. 列表页搜索后 URL 会保留查询参数
2. 列表页筛选和页码变化后 URL 会同步更新
3. 刷新列表页后仍能恢复同样的筛选结果
4. 从列表进入详情再返回时，能回到原页码和筛选状态
5. 从首页直接进入详情时，仍保持现有返回逻辑
6. 前端构建通过

---

## 九、实施结论

`T-P0-14` 的最终实施方案确定为：

1. 用路由查询参数保存 MTM 列表页的最小上下文
2. 用详情页来源标记恢复列表返回路径
3. 不扩展新的后端接口和额外筛选能力
4. 以最小改动修复“刷新即丢、返回即丢”的体验断点
