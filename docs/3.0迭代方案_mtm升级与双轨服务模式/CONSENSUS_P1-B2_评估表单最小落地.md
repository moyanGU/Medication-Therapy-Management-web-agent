# CONSENSUS P1-B2 评估表单最小落地

## 1. 明确需求描述

- 为 MTM 服务单新增最小可用的“评估表单”主路径。
- 用户可以：
  - 从服务单详情页进入评估页
  - 手动保存评估草稿
  - 手动完成评估
  - 返回详情页查看评估摘要

## 2. 验收标准

- 存在独立评估页，且路由可访问。
- 存在 3 条评估接口：
  - `GET /api/mtm/service-cases/{id}/assessment/`
  - `PUT /api/mtm/service-cases/{id}/assessment/`
  - `POST /api/mtm/service-cases/{id}/assessment/complete/`
- 详情页存在唯一主评估入口：
  - “开始评估” / “继续评估” / “查看已填评估”
- 草稿保存成功后不写 `completed_at`。
- 完成评估成功后写入 `completed_at`。
- 完成评估后不自动把服务单推进到 `intervening`。
- 详情页能回看最小评估摘要。

## 3. 技术实现共识

### 3.1 数据模型

- 继续复用现有 `MTMAssessment`。
- 本轮不扩字段。

### 3.2 表单字段范围

- 五维评分：
  - 适宜性
  - 有效性
  - 安全性
  - 依从性
  - 经济性
- 综合风险等级
- 问题清单
- 评估总结

### 3.3 交互策略

- 采用“手动保存草稿”。
- 本轮不做自动保存。
- 问题清单使用“每行一项问题”的低门槛录入方式。
- 风险等级使用固定选择项。
- 评分允许在草稿阶段未填完整。

### 3.4 完成策略

- 采用“仅保存完成状态”。
- 保存完成评估时：
  - 写入评估内容
  - 写入 `completed_at`
- 不自动把服务单推进到 `intervening`。

### 3.5 入口策略

- 详情页作为唯一默认入口。
- `interviewing` 阶段若问诊已完成，应优先引导填写评估。
- 避免“进入评估”和“开始评估”并列成两条主路径。

## 4. 任务边界限制

- 不在本轮接入干预计划编辑。
- 不在本轮联动随访编辑。
- 不在本轮改变现有状态机规则。
- 不新增模拟数据。
- 不改变统一响应格式。

## 5. 集成方案

- 后端沿用 `MTMServiceCaseViewSet` 的 detail action 风格。
- 前端沿用 `P1-B1` 的页面结构、API 封装、路由命名和详情页入口组织方式。
- 详情页继续复用已有评估摘要展示区，不另开第二套摘要组件。
