# ALIGNMENT P1-B3 干预计划表单最小落地

## 1. 原始需求

- 承接 `P1-B2` 的评估表单最小落地，进入 `P1-B3`：干预计划表单最小落地。

## 2. 当前项目上下文

### 2.1 已有基础

- 后端 `apps.mtm` 已存在 `MTMPlan` 模型。
- 当前模型字段包含干预计划所需核心信息：
  - 干预措施：`interventions`
  - 优先级：`priority`
  - 患者确认状态：`patient_confirmation_status` (默认 pending)
  - 患者确认说明：`patient_confirmation_notes`
  - 确认时间：`confirmed_at`
- 服务单详情页已经存在“干预计划摘要”展示区，但当前没有独立填写入口。
- 详情页状态动作支持 `assessing -> intervening`。

### 2.2 与 P1-B2 的衔接关系

- `P1-B2` 已完成：
  - 独立评估页
  - 评估读取 / 草稿保存 / 完成接口
  - 详情页唯一评估入口
  - 手动保存草稿
  - 完成只写 `completed_at`
- `P1-B3` 适合沿用同样的主路径风格：独立页面 + 读写接口 + 保存草稿与完成。

## 3. 当前缺口

- `MTMPlan` 模型缺失记录药师完成填写的 `completed_at` 字段。
- 无独立干预计划表单页。
- 无干预计划读取、保存草稿、完成的 API 接口。
- 详情页没有“开始计划 / 继续计划 / 查看已填计划”的唯一入口。

## 4. 本轮任务边界

### 4.1 本轮要做

- 为 `MTMPlan` 模型补充 `completed_at` 字段，并创建数据迁移。
- 新增独立干预计划页，承接最小干预计划填写。
- 新增计划读取 / 保存 / 完成 3 条接口。
- 在服务单详情页接入计划入口。
- 保持页面文案为普通用户可理解的人话。

### 4.2 本轮不做

- 不实现患者侧确认功能，本轮仅针对药师端起草干预计划。
- 不把计划完成和进入随访自动绑定。
- 不做自动保存。

## 5. 默认主路径判断

- 计划表单页继续采用“手动保存草稿 + 手动完成”的双按钮模式。
- 完成计划时只写 `completed_at`，不自动把服务单推进到 `following_up`。
- 服务单状态推进仍保留人工显式动作，和表单完成解耦。
- `interventions` 在前端用“每行一项措施”收集，提交时映射为结构化数组。

## 6. 关键实现假设

- 只有在评估已存在且已完成时，才推荐进入干预计划主路径。
- 优先级用固定枚举承接。
- 干预措施允许为空草稿；完成时再做最小必填校验。
